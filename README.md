# 学期OS（SemesterOS）

面向大学生的学期事务管理 App：将课表、作业、考试和临时通知转为可追溯的事项，分析时间余量，生成个人计划，并在现实安排变化后进行最小扰动重排。

## 当前状态

当前为 **0.1.0 课表与事项测试版**，已实现 Android 工程、注册登录与恢复、学期设置、教务导入、周课表/列表、作业/考试/个人任务、文字AI解析确认、本机提醒，以及可学习时间、进度更新、计划余量分析、自动排程、课次变化确认和个人计划最小扰动重排。课程事务中心、考试复习与改期确认、学期时间轴已接入。第一版面向 Android，iOS 后续适配。

已接入 Flutter、FastAPI、PostgreSQL、服务端DeepSeek文字解析、OR-Tools CP-SAT排程，以及本地OCR/ASR媒体录入。自然语言修改个人任务/提醒和规划请求已接入，均需先核对再确认。依赖锁在`apps/mobile/pubspec.lock`及`services/api/requirements.lock`。用户于2026-09-20确认本人教务课表已成功导入；逐项完整性、其他认证入口和物理手机兼容性仍需分别核对。

界面已按03的校园活力风调整：今日课程状态与彩色卡片、可切换的周视图/日程、课程详情、学期管理和导入确认。周视图将重叠课程并列显示，大字体自动使用完整日程列表；示例界面截图在本机`output/verification/ui/`，来自Flutter渲染测试，不含真实学生数据。

## 用一句话修改

“＋记录 → 用一句话修改事项 / 提醒”，或事项详情中的“一句话修改”：例如“Java报告还需要两小时”“Java报告提醒改到周四晚上八点”。先匹配当前学期的事项，再展示修改前后差异；同名事项、多条提醒需要明确选择。“周四晚上”不自动补成20:00，需补充具体时刻。支持任务标题、剩余工作量、拆分设置，以及单条提醒的新增、修改或停用。

“把Java报告重新安排一下”先核对任务范围和真实剩余工作量，再生成计划候选，候选仍需独立确认。新增安排可限定明确起止时刻；重排只移动所选任务，其他任务和锁定块保持原位。现实课程/考试时间、截止、完成状态和解锁使用对应的专用确认入口。图片中的修改要求还需确认是本人意图；来源文稿修改后必须重新核对。

文字/媒体解析会将这些意图转入修改页。输入草稿按账号、学期及详情事项保存，最近50条请求可重新查看。AI不可用时仍可使用手工事项、提醒及计划入口。本批新增数据库迁移`0009_operations`，启动API脚本会自动执行。

## 图片通知与语音快速记录

“＋记录 → 图片通知录入 / 语音快速记录”：选图或录音，上传并识别后，对照原图/回放录音修正文稿，核对原消息时间，再解析并确认事项。图片支持单张JPEG/PNG/WebP，输入最多10MB、2000万像素；App录音为16kHz单声道WAV，最多120秒/20MB，进入后台会停止录音。多条通知先在文稿中选定需要处理的一条，不承诺一次导入整张课表或整场考试表。

OCR使用RapidOCR，语音使用SenseVoice，均在API主机的独立worker进程运行；原媒体不发送给DeepSeek，结构化解析只发送校对文字与课程候选。来源与文字草稿按账号/学期保存，重启可恢复，退出账号清理本机缓存。识别可取消或重试，取消后的迟到结果不会覆盖新文稿；没有录音权限或识别失败时仍可手工填写。

事项详情可回看关联来源；删除服务端原文件会保留识别文字、校对稿及已保存事项。私有媒体在`.local-data/media`，模型在`.local-data/models`，两者都不进入Git。首次准备好API环境后，另开终端下载语音模型（本机已完成）：

```powershell
& services/api/.venv/Scripts/python.exe scripts/setup_media_models.py
```

API默认管理一个独立识别worker，数据库保存排队状态与租约。异常中断的作业在租约过期后可重新领取；已开始的底层推理不保证立即停止，但取消后不接纳其结果。数据库与私有媒体目录需一起持久化；Compose已配置媒体卷及只读模型目录，容器镜像完整构建仍待独立验收。

## 课程、考试与学期时间轴

点击课表中的课程进入课程事务中心，查看明确关联的作业、考试、学习任务、有效课次和调停课记录；从这里新增事项会预选该课程。只按学校明确的课程标识归组多条授课模式，不按同名猜测关联。

“学期”页按周展示重要事项与变化，日期未知的事项单列。周负荷展示未来可用时间、有效个人计划和已知截止工作量；截止集中的任务可以提前完成，不以单周容量直接推断排不下。原来的学期切换、新建和导入入口保留在“管理学期与课表”。

“学期 → 考试中心”可查看正式/暂定考试、提醒、关联复习任务及计划覆盖。复习工作量由用户选择建议值或自定义，也可关联已有个人任务；考试时间不明确时，不自动创建精确复习截止。已有复习通过任务详情更新剩余工作量和进度，计划覆盖不等于实际完成。

考试改期先预览考试、提醒、复习截止和已有计划的影响，再确认保存。同步未完成复习截止需单独选择；提醒在核对期间被改动会使预览失效。确认回执先校正本机考试与复习提醒，后续网络失败不沿用旧提醒。个人时间块保持原位，需要时再进入重排。

## 现实变化与个人重排

进入“计划 → 调课 / 停课 / 现实变化”，粘贴通知交给AI提取建议，或手工填写变更依据。明确选择单次课次和新时间，预览变化前后、受影响计划、任务余量及固定冲突，再确认现实变化。放假停课逐项选择受影响课次，不自动停掉整学期；补课和固定活动可新增起止时间。跨天安排分条记录。原周期课程保留，变更只作用于确认的课次。

现实变化确认后点“分析最新安排并生成重排候选”，或在个人计划列表点“尽量少改动，重排已有计划”。系统纳入全部已有未来块，保持ID与时长，先最小化移动任务数，再最小化开始时刻偏移合计；锁定、已开始及预留时间内即将开始的块固定。页面展示原时刻与新时刻，用户独立确认后才移动。不能完整安排时保留旧计划，不静默删除工作。

本轮重排不补排从未纳入计划的剩余工作，补排仍使用“生成计划”。撤销重排只在旧位置仍符合最新现实约束时恢复；例如旧位置已被调来的课程占用，会明确拒绝。考试改期已有考试中心的专用确认流程，文字通知自动匹配考试对象仍待接入。批量教务重新导入的差异应用也仍需后续接入。

## 自动生成个人计划

进入“计划 → 生成计划”，选择未来7/14/28天、开始前预留时间、拆分长度和参与任务。窗口内有明确截止的任务按剩余工作量安排；其他任务需要填写本轮目标。目标包含本轮已有的有效覆盖，系统只补足缺少的部分。不可拆分任务必须连续完成，不能用多轮小目标绕过限制。

生成后先核对每段时间、已有覆盖、本轮新增和未安排工作，再点“确认应用”。容量不足时可主动查看部分方案，明确接受未安排分钟后才能保存。这个入口只追加安排，课程、考试及已有个人计划保持原位；移动个人计划使用独立的重排入口。任务或课表变化、候选过期时需重新生成。

个人计划可在“计划”和“今日”查看，支持锁定、取消以及撤销最近应用且尚未修改/开始的整批方案。排进日历不代表完成工作，仍需通过“更新进度”确认剩余工作量。完成或取消事项时会先列出受影响计划，锁定块需额外明确确认；调整学习时间也会提示冲突并保留原计划供核对。

## 可学习时间与计划余量

进入“计划 → 学习时间”，设置每周可学习时段及临时禁排，核对前后变化后保存。新设置默认空白，示例只有主动填入并确认后生效。事项详情可通过“更新进度”确认新的剩余分钟和实际投入；剩余0需明确确认完成。

任务卡显示单项余量和共同窗口缺口，点击可查扣除固定安排后的容量及计算依据。需要确认截止、剩余工作量和最早开始口径（编辑事项的更多设置）；考试可补充结束时间。旧记录缺失信息保持未知，不自动填默认工作量或考试时长。

分析扣除课程、完整考试时段与禁排的并集，并检查未排程任务是否争用同一容量；不会把单项正余量当作整体安全。有效个人计划参与容量核算，自己的覆盖不重复扣除，过期时间块不视为工作完成。课表、设置或任务变更立即使旧结果失效，前台定期刷新，离线/过期不显示旧精确余量；容量检查与具体排程分别展示。

## 事项与文字解析

通过“＋记录”选择文字快速记录、作业、考试或个人任务。解析结果先进入核对页，可修改类型、标题、课程、时间和提醒；只有确认后才保存。只有日期/周次时保留原精度，耗时未知可留空。“计划”入口提供事项列表、个人计划、完成/取消操作和自动排程入口。

服务端从仓库根目录的本机`.env`读取`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`和`DEEPSEEK_BASE_URL`；客户端不含密钥。修改配置后重启API。未配置或模型异常时保留输入原文和手工填写入口。

事项详情可独立增加、修改或停用提醒。首次使用请点“开启或检查系统通知”；拒绝权限仍可保存规则。采用普通系统定时提醒，界面显示的是同步/安排状态，不代表已送达。日期改动会重算相对提醒；过期提醒不补发，需核对或重复时刻的规则暂停。完成、取消和退出账号会撤销本机相关提醒。

## 本机运行（PowerShell 7）

先启动 Docker Desktop，并准备 Python 3.12、Flutter 和 Android Studio 模拟器。根目录执行：

```powershell
# 终端1：创建本地私有配置、启动PostgreSQL、迁移并运行API
pwsh -File scripts/dev.ps1 -Action Api

# 终端2：自动选择已连接的Android设备；没有设备时启动已有模拟器
pwsh -File scripts/dev.ps1 -Action Android

# 验证：PostgreSQL独立测试schema + Flutter测试及静态分析
pwsh -File scripts/dev.ps1 -Action Test
```

`Test`动作还会执行教务读取脚本的JavaScript回归，需要Node.js 18或以上版本；也可单独运行`node --test apps/mobile/test/haut_reader_test.cjs`。回归包含学校改写`Array.prototype.filter`回调顺序的场景，使用合成数据，不保存真实课表。

API使用`http://127.0.0.1:8871`，模拟器通过`http://10.0.2.2:8871`访问；PostgreSQL只绑定本机`55439`端口，避免占用已有项目的`55432`。首次运行脚本生成`.env`，不输出密码。API已在运行时无需重复启动同端口服务。

Android启动脚本优先使用唯一已连接设备；没有设备时默认启动`Medium_Phone_33`，等待Android系统和安装服务就绪后再运行App。多个设备时用`-Device`指定，其他虚拟设备用`-Emulator`指定；原来的`-Device emulator-5554`命令也支持自动启动该端口的模拟器。启动日志保存在`tmp/android-start/`，默认等待150秒，不清空模拟器数据。

启动脚本会为本次构建定位本机JDK 21；也可通过`SEMESTEROS_JDK_HOME`明确指定，不修改全局Java配置。图片/录音/回放涉及原生插件，更新后需完整重新运行App，单纯热重载不足以加载新插件。

用 Android Studio 打开`apps/mobile`目录。当前验证设备为`Medium_Phone_33`（Android 13）。本次导出的调试包只含x86_64，用于该模拟器；物理手机需另构建适合其架构的包。调试包允许本地HTTP，正式发布需要HTTPS入口和独立签名配置；本批不发布正式签名包。

完整容器运行配置在`deploy/compose.yaml`，可执行`docker compose --env-file .env -f deploy/compose.yaml up --build`；当前实测组合为PostgreSQL容器加本机Python API，API镜像构建未作为本批完成证据。

## 教务与导入边界

- 正常流程：注册自己的学期OS账号 → 选择学校校历第1周的周一（必填），核对学期/节次 → 记录 → 从学校教务导入 → 学校原页自行登录 → 进入个人课表查询 → 读取 → 核对来源学期和课程 → 确认保存。日期通过日历选择，不会自动采用示例日期；缺失或格式错误会在对应字段下提示。
- 只从`jwglxt.haut.edu.cn`已登录课表页读取白名单字段；统一认证的其他跳转域名尚未实测，当前会阻止未知跳转。
- 学校服务器返回的同域HTTP重定向会改为对应HTTPS地址，在原WebView会话中继续访问。反复跳转会暂停并提示刷新；未验证地址的提示仅显示协议与域名，不显示认证参数。登录页面卡在“登录中”时，更新App后先刷新原页面，再重新输入登录信息。
- 空响应或无法识别的周次/节次不会当作导入成功；首次读取真实数据后还需检查学校的实际返回格式。
- 读取脚本使用逐项白名单提取，避开学校页面改写的数组过滤方法。调试更新后可先小写`r`热重载，再点击读取；脚本不复用旧字符串缓存，尽量保留已经登录的WebView会话。
- 本批支持新增和精确重复检查；教务同一课程的时间模式变化会标为待核对，暂不自动应用调课。明确手工添加的另一次授课允许保存。
- 离线可看已缓存的周次，已知过期或从未缓存的周次会提示需联网；退出账号清理该账号本机缓存与教务会话。
- 测试账号和手工构造课程用于验证，不作为真实学生试用数据。

## 工具链兼容性

已实测Flutter 3.44.2 / Dart 3.12.2，使用本机已有的Gradle 8.14、AGP 8.11.1、Kotlin 2.2.20；工程保留HTTPS Maven镜像与官方源。Windows跨盘Kotlin增量缓存存在路径错误，因此本项目关闭该增量缓存并使用进程内编译，未修改其他项目。

构建JVM由`apps/mobile/android/gradle/gradle-daemon-jvm.properties`固定为 **Java 21**，需要本机安装JDK 21。它优先于Android Studio自带JBR和`JAVA_HOME`选择Gradle构建进程，因此IDE升级到JBR 25后仍使用兼容的构建JVM；不修改全局Flutter或Java配置。本机已检测到`C:\Program Files\Microsoft\jdk-21.0.4.7-hotspot`，仓库不硬编码这个路径。若出现只写着`25.0.x`的构建异常，先检查此配置是否存在；依赖列表的“有新版本”提示不是同一个问题。[Gradle JVM规则](https://docs.gradle.org/current/userguide/gradle_daemon.html#sec:daemon_jvm_criteria)

固定`material_ui`/`cupertino_ui` 1.0.0以适配当前Flutter SDK；较新版本引用了此SDK没有的注解。Drift 2.28.2与sqlite3_flutter_libs 0.5.39避免当前网络下SQLite 3.x原生资源下载失败。更新依赖需重新验证，不能直接清除锁文件升级。

媒体插件固定`image_picker 1.2.0`、`image_picker_android 0.8.13+5`、`record 6.1.2`、`record_android 1.4.5`、`just_audio 0.10.5`和`audio_session 0.2.2`，保持与本项目Gradle 8.14/JDK 21兼容；当前更高版本的部分插件使用AGP 9，不能直接只升级Dart依赖。插件构建脚本也使用项目现有HTTPS Maven镜像。

## 数据与开发约定

- 教务密码、Cookie、模型密钥和签名密钥不进入仓库。
- 临时文件、设备配置和构建产物由 `.gitignore` 排除。
- 合成演示数据与真实试用数据分开；示例导入不视为真实认证导入成功。
- 保留来源、版本和确认记录；AI失败后基础事务仍应可管理。
