# 拾日

拾日是一个给在校学生用的 Android 日程 App。课表、群消息里的通知、待办、考试，还有你自己排的复习时间，都放在同一个学期里管。

最常见的用法是这样：群里有人说“明天 9:15 到 A301 开会”，你把这句话或者截图丢给助手。它会去翻你的课表，看那个点有没有课、有没有别的事撞上，再告诉你“9:15 到 A301，结束时间没提”。你核一遍，觉得对，才存。存之前能看清楚它准备写什么，存完有回执，写错了能撤。

当前版本 **1.1.1，Android 构建号 12**。客户端是 Flutter，后端是 Python + FastAPI，正式库用 PostgreSQL。文字助手接 DeepSeek，图片 OCR 和录音转写在服务端本地跑，学习排程交给 OR-Tools 求，标签归类是纯规则，不调模型。

## 能做什么

| 板块 | 具体内容 |
| --- | --- |
| 今日 | 当天安排、下一项、待办、考试提醒、学习空档；首页放什么可以自己调 |
| 日程 | 周课表和列表两种看法，切周、跳日期，手动加日程；时间说不全也能存 |
| 课程与学期 | 建学期、改作息、导入或手录课程；调课、停课、请假都落在具体那一次课上 |
| 助手 | 文字、截图、录音都能喂；先查已有记录，再补信息、纠错，出预览让你核对，确认后才有回执和撤销 |
| 任务与学习 | 待办、作业、考试、批量操作、记进度；排学习时间要先预览，排完能锁定某几段，也能重排 |
| 标签 | 按标题、课程、用途自动归类，同类的自动合并；点标签能看到跨学期的事项 |
| 查找与统计 | 课程、日程、待办、原文全文搜索；按时间、分类、标签看统计 |
| Android 入口 | 本地提醒、离线延后、桌面日程卡、快速记录、系统分享、你自己开的实时通知 |
| 账号与数据 | 注册、登录、恢复码、资料、反馈、导出 JSON、删来源附件、注销 |

表里没写的基本就是没做，别自己脑补。每项的规则和限制在[完整使用说明](docs/产品规则.md)；想看某个功能落在哪个文件，翻[功能清单](docs/功能清单.md)。

## 装一个试试

[GitHub 上的 v1.1.1 发行版](https://github.com/Keleoz-Cyber/SemesterOS/releases/tag/v1.1.1)，里面有正式 APK、SHA-256 校验文件和构建信息。装之前顺手对一下哈希，别装错包。

最低 Android 7.0（API 24），带 armeabi-v7a、arm64-v8a、x86_64 三种。Android 16 上那套增强通知得系统放行，最后长什么样由厂商决定，我们控制不了。

## 从源码跑

要 Python 3.12、Docker Desktop、满足 `^3.12.2` 的 Flutter、Android SDK、JDK 21。想把学校网页读取也跑起来，还得装 Node.js。

先把 [.env.example](.env.example) 复制成 `.env`，把数据库和模型配置填上。

后端在仓库根目录开一个 PowerShell：

```powershell
.\scripts\dev.ps1 -Action Api
```

App 另开一个窗口：

```powershell
.\scripts\dev.ps1 -Action Android -Device emulator-5554
```

模拟器连 `http://10.0.2.2:8871`，正式包连 `https://semesteros.keleoz.com`。真机连接和环境变量在[移动端说明](apps/mobile/README.md)，上线和打包看[部署与维护](docs/部署与维护.md)。

## 代码放哪

| 目录 | 说明 |
| --- | --- |
| `apps/mobile` | Flutter 页面、Android 系统接入、组件测试和流程测试 |
| `services/api` | 接口、数据模型、助手工具、规则与排程、迁移、pytest |
| `scripts` | 开发启动、构建、验证、看反馈、清理 |
| `deploy` | Compose、Nginx、备份、恢复演练、云端部署脚本 |
| `design-system` | 设计令牌、组件和动效说明 |
| `docs` | 使用、功能、开发、接口、测试、运维、参赛材料 |
| `output` | 本机产出的 APK、验证记录、构建信息，不进 Git |

文档从[文档目录](docs/README.md)进。要读的通常是这几篇：[后端说明](docs/技术契约.md)、[接口索引](docs/接口索引.md)、[功能清单](docs/功能清单.md)、[测试与比赛说明](docs/测试与比赛说明.md)。

测试结果、发行文件、已知限制都在[版本与交付说明](docs/交付说明.md)。合成测试、用户给的意见、真机跑出来的记录，各自标了来源。没测过的准确率、用户量、提效比例，我们不写成成果。
