CourseMeeting、CalendarEvent、StudyItem、PlanBlock 保持各自事实模型，查询投影统一展示，不产生第二份可编辑课程事实。媒体、候选、修改、现实变化、计划及 AgentThread/AgentRun 保存归属和版本；结构见 models.py。学校密码/Cookie不进入业务来源。

## 时间、状态与占用

- 精确时间存 UTC、保留 IANA 时区，当前默认 Asia/Shanghai。校历用本地日期、已确认首周周一、总周数、原节次；假期/调课是例外，不重新编号周次。
- `precision=exact/date/week/range/unknown` 与 `meaning=deadline/start/window/candidate/course_anchor/all_day/unspecified` 分开。日期、周次和范围不能伪装为午夜钟点；仅明确全天使用 date/range 的 all_day。
- 以整数分钟计算真实边界；用户选时的吸附不改变校方真实钟点。区间是 `[start,end)`，开始点、提前到场区间和完整区间按[时间事实守卫](../services/api/app/fixed_conflict_guard.py)核对。
- 确定性、用户审核、生命周期、是否预留、控制权及字段证据分别保留。用户确认暂定通知不使其成为正式通知；参考考试可以确定但不占时间。
- 未知结束不延伸成整天，普通日期不封锁一天；已请假/准备请假/免听采用同一[出勤语义](../services/api/app/course_participation.py)供容量、日历、统计和提醒读取。
- 课次身份保留原课程/系列/周次关系。单次调课不靠移动后的日期重新造身份；校历更正重放明确例外，普通课次随新骨架展开，避免相邻周 ID 复用。

## 写入、隔离与失败

身份来自服务端会话，用户和学期是所有查询、关联、候选、媒体及缓存的边界。模型给出的对象 ID 不可信；路径 ID、客户端上下文和外键仍须归属校验，无权对象不泄露存在性。

先读取一致快照，模型和求解在短事务外运行。正式保存锁定有关学期并复核对象版本、学期 revision 和最新依赖；过期预览返回冲突，不能覆盖新事实。业务写入、修订历史、幂等结果和可恢复回执一同提交。客户端超时不等于未保存。

确认绑定服务器候选、所选组、参数和版本；模型不能签发确认凭据。固定安排保存端重新核对实际冲突及所选出勤授权；失败原子回滚，控制字段不混入正式业务 payload。完成任务涉及未来计划取消时，一张确认页明确范围，进度与取消一起保存。

撤销是受版本与当前约束限制的补偿事务，不任意回滚数据库。仅恢复该操作改变的业务；已确认现实通知不随个人计划撤销。删除课程保留相关任务并解除关联；删除学期清理所示范围，其他用户/学期不受影响。媒体删除任务与数据库删除同事务提交，文件失败可重试。

会话删除不可恢复；内部删除标记/引用保护既有业务回执，不提供恢复 API。取消作业不能撤销已保存业务；取消、删除、来源修正或预览替代后，迟到结果不得重新发布。

## Agent 接口与上下文

当前前缀 `/api/v1/agent`，完整参数见[agent_api.py](../services/api/app/agent_api.py)和[agent_media.py](../services/api/app/agent_media.py)：

| 接口 | 作用 |
| --- | --- |
| `POST /threads`，`GET /threads`，`GET /history` | 创建/列出对话、游标历史 |
| `GET /threads/{tid}`，`DELETE /threads/{tid}` | 分页消息、不可恢复删除 |
| `POST /threads/{tid}/turns` | 提交本轮内容，202 返回运行引用 |
| `GET /runs/{rid}`，`GET /runs/{rid}/cards/{card_id}` | 真实状态、回执与分页卡片 |
| `POST /runs/{rid}/revise`，`/cancel` | 编辑重答、取消未完成工作 |
| `POST /runs/{rid}/decision`，`/selection-preview` | 当前候选确认、所选组预览 |
| `POST /runs/{rid}/request-undo` | 生成受保护的撤销请求 |
| `POST /media-runs`，`GET /media-runs/{id}`，`POST /media-runs/{id}/cancel`，`/retry` | 私有媒体识别及失败恢复 |

Agent 通过受控业务工具查询日程/事项/来源、查空档、准备修改、安排或重排，再读取真实结果。不能执行任意 SQL/HTTP、模拟手机点击绕过业务服务，或把来源里的指令当作权限。

上下文是本轮原话/来源、最近已确认对象引用、相关真实状态和用户明确偏好。账号/学期切换后旧引用失效；浏览范围不覆盖真实今天或消息时间。长期偏好不能由一次临时要求推断。完成后读回执，模型末段超时不抹去已完成查询或已提交写入。

模型格式/工具参数须服务端校验，工具失败保留进展并准确说明未保存。工程循环和输入上限以代码为准，不解释为学校授权要求；例如批量组上限不等于每个课次都要独立确认。

## 容量、风险与排程

在明确最早开始和截止范围内，`U` 为用户允许安排的时间，`F` 为固定占用/禁排并集，`P_other` 为其他任务有效未来安排，`R` 为本人确认剩余量：

```text
单任务可用时间 A = minutes(U \ (F ∪ P_other))
单任务余量 S = A - R
截止窗口缺口 G = max(0, 窗口内全部剩余需求 - 窗口容量)
```

自己的有效未来计划保留在 A 中；窗口需求已包含的计划不再扣容量；固定重叠按并集。计划过去不减少 R。窗口缺口包含未排任务，缺口为零不证明连续块、锁定或拆分约束下可行。例：4 小时容量、两个各 3 小时任务，整体至少缺 2 小时，不能用各自正余量宣称低风险。

[capacity.py](../services/api/app/capacity.py)返回计算范围/时间/revision、完整性、余量、窗口缺口和原因码。`risk-v1` 中逾期、实际硬冲突、窗口超载等优先；无上述问题而余量低于 `max(30分钟, 0.2×剩余量)` 为偏低。缺资料或旧结果保留未知/待更新，客户端不为视觉效果重算等级。阈值是工程规则，不是经过学业预测验证的模型。

排程仅安排用户可控任务；课程、参与活动、预留考试和未解锁计划是硬约束。整数分钟保留真实时间，支持用户明确的天数/块长；不能把每次 5 分钟改成总共 5 分钟，也不能擅自拆开要求整段的任务。分块限制与数学上无解分别说明。

本轮目标包括窗口内有效已有覆盖，扣除窗口外有效覆盖，不重复安排同一工作量。返回已有覆盖、新增/调整、未安排分钟；一周方案不能称完整学期方案。完整/部分/不可行/超时/输入限制/分块限制分别返回，只有经独立校验的可行方案可接受。

重排先满足硬约束和工作量，再减少移动任务数、开始时刻偏移，最后处理偏好。保留块身份、锁定和历史；只有求解状态证明最优才能称最优，可行不等于最优。局部方案不宣传为全局最小扰动。

## 提醒与客户端状态

相对提醒需要已确认时间锚点；绝对提醒使用独立触发时刻，可用于无时间考试的“核实通知”。提醒用途、用户启用意愿、安排状态及实际送达分别记录。任务/考试预设可独立选，不默认全开；开始复习提醒不自动生成复习计划。

改期重算相对提醒，过期不集中补发；绝对提醒不静默平移，不再符合用途时提示核对。取消/完成/已请假撤销相关未来通知；撤销失败或云端同步失败如实显示。多设备离线期间本机清单可能旧，联网后校正。

Android 使用 `flutter_local_notifications.zonedSchedule` 注册系统 AlarmManager；准时提醒权限可用时 `exactAllowWhileIdle`，否则 `inexactAllowWhileIdle`。可见投递还需通知权限。返回桌面/移除最近任务通常不要求 Flutter 持续运行；设置中的强行停止属于不同状态，会影响系统安排。启动、重启、包更新及权限变化有清单重建，实机/OEM投递仍须设备验收。实现见[android_notifications.dart](../apps/mobile/lib/features/items/android_notifications.dart)。

账号/学期/请求代次隔离缓存、草稿、录音和播放。退出清理本机令牌、私有副本、学校会话及旧监听器；离线仅展示缓存/草稿，不离线接受规划或应用现实变化。恢复后完整刷新事实与提醒；成功前不使用乐观完成动画或“已保存”文案。
