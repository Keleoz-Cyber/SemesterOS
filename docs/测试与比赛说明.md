## 发行与设备验收

- [ ] 当前源码相关回归、迁移兼容与静态分析通过，跳过环境及原因明确。
- [ ] 真实 App 走通注册/资料、学期/节次、学校或匿名导入核对、未知时间记录、修改/撤销、个人计划、提醒和重新登录保留。
- [ ] 只读查询无业务写入；预览未确认不保存；重复提交与保存超时不重复创建。
- [ ] Release 包名、版本、签名、正式 API、三 ABI、16KB 对齐、通知图标和学校资产核对；覆盖安装后拉回哈希与交付包一致。
- [ ] 正式服务健康、未登录鉴权、API/worker版本、迁移及现有数据保留核对。
- [ ] 普通手机宽度、320/360dp 大字、横屏、长中文、键盘/录音、空/加载/刷新/失败/确认条件检查。
- [ ] 真实学校原页登录、当前学期逐项核对、重新导入与失效重登，说明网络与读取/确认范围。
- [ ] 物理手机选图、有效录音/回放、通知权限与准时提醒权限，实际后台、锁屏、重启投递和厂商限制检查。

最后两项没有对应设备/账号时保持未验证。正常移除最近任务与设置“强行停止”分别测试；系统清单中 scheduled 不是已送达。模拟器提醒送达与 Profile 样本只描述该设备，不外推 OEM 或稳定 60fps。

## 指标与公平实验

解析记录类型、时间/截止、课程关联、确定性、结构化成功、遗漏/幻觉；修改另记意图、目标和字段正确率、追问及错误执行。关键未确认执行、错对象、未经请求改课均计错误。

规划分别统计完整、部分、不可行、超时和失败；已接受新方案的硬冲突、锁定误移动、截止违反目标为零。现实新通知造成的原有冲突须如实报告，不能删事实使指标好看。记录未安排分钟、移动任务数（任务 ID 去重）、时间块数、开始偏移与时限/求解状态；少排任务不能赢“更低扰动”。

体验从结果可操作至正确保存计时，包含核对/纠错/失败/展开设置；模型端到端延迟另报。性能写设备、模式、样本数、冷/热态、p50/p95/错误率，构建或光栅阶段超阈值不称系统丢帧，原型帧率不称 Flutter 性能。

| 实验 | 方法与评价 |
| --- | --- |
| 手工记录 vs AI 快速记录 | 相当难度的 10 条通知，平衡顺序/记忆效应；含最终核对时间、日期错误、遗漏、操作次数 |
| 截止排序 vs 余量分析 | 工作量/容量不同、多个任务争用窗口、正余量却无连续块；预标可行性与缺口，比较误报/漏报和实际安排 |
| 全量重排 vs 最小扰动 | 相同事实/任务/工作量/锁定/粒度/求解预算；完整可行方案先比移动任务数，再比偏移，报告所有失败/无解/超时 |

如比较纯模型、贪心、CP-SAT或增量策略，应固定输入与判据，不故意打乱基线。拆分/合并的块匹配预先定义，模型调用次数、耗时和成本据实记录。个性化和学期复盘没有真实记录时不报告成效。

## 赛事规则与材料

参赛方向：2026 第八届全球校园人工智能算法精英大赛，算法创新赛赛题 2“AI+软件创新”。以下依据用户提供的[规则 PDF](2026AIC算法创新赛赛题规则汇总260506-1.pdf)，2026-09-19 核验通用要求第 2—3 页和软件创新第 7—10 页；当时[官网入口](https://www.aicomp.cn/tracks/tracks-2/3792.html)抓取超时。这是所提供规则版本，不表示已经排除后续补充通知。2026-10-15 只是团队原完成目标，不能当官方截止日期。

| 要求 | PDF 依据 |
| --- | --- |
| 完成的软件核心功能，AI 与业务结合，软件/算法说明、演示、测试及运行部署信息 | 第 7 页；移动端允许，平台/环境/语言不限 |
| 评分 | 第 8 页：创新性20、技术实现20、功能完整性20、方案完整性20、应用价值15、总结展望5 |
| 名称/简介 | 第 3 页：名称不超过20字，简介不超过300字 |
| 演示视频 | 第 3 页：MP4，3—5分钟，300MB以内 |
| 方案/答辩/佐证 | 方案按官方模板 PDF 不超过10M；答辩 PPT 保存 PDF；佐证合并一个 PDF |
| 大型材料 | 按规则上传百度网盘，命名“参赛团队编号-赛题名称-作品名称-XX（材料名称）”，永久链接并自动生成提取码 |
| 匿名 | 提交方案/视频/答辩等不出现参赛团队学校名、Logo、指导教师等身份信息；截图、教务页面、文件名和错误页一并核对 |

真实接入内部证据与匿名展示分开；学校选择功能名与提交材料匿名要求不是同一事情。比赛用独立演示账号、合成课表和匿名来源，明确“演示数据”；不能制作假登录成功、把示例装载说成真实认证、将构造样本说成学生试用。演示的实时解析与求解失败应如实失败或手工处理，不能换预置成功。

真实学生试用须自愿并脱敏。至少一轮是团队内部质量目标，原规则没有固定人数/轮数要求。未开展用户试用、公平实验、查新或性能对照时，不编数字填材料。

## 演示主线与创新表达

3—5 分钟建议：痛点约25秒 → 示例课表与数据说明约30秒 → 文字/语音/图片通知与确认约35秒 → 学期节点与可复算余量约35秒 → 个人规划/锁定约30秒 → 调课或组会触发冲突/重排/确认约55秒 → 更新结果约30秒。

重点是可信事项结构化、基于容量和工作量的风险、现实变化下少移动个人计划。OCR/ASR、聊天框、通用框架或 CP-SAT 本身不包装成独立原创算法。调课不必然降低余量：展示旧时段是否在可学习范围、新时段是否占截止前容量及前后明细；等量交换允许余量不变。现场方案与固定夹具不同也照实展示，不硬编码“只移动一项”或“5小时降至3小时”。

提交前连续跑通“导入 → 输入 → 核对 → 展示 → 分析 → 规划 → 现实变化 → 影响 → 重排 → 确认/撤销”，检查来源、暂定/未知、锁定、不重复保存、AI异常下基础日程可用。材料用“在测试范围内”“根据已记录信息”“经用户确认”等可追溯表述，不承诺永不忘事、全部准确或自动修改学校安排。
