# 第四批：自动排程候选与确认

日期：2026-09-20。分支：`codex/android-foundation`。本批在已确认学习时间和任务工作量上接入OR-Tools CP-SAT，完成初次排程、核对、确认和个人计划管理。已有块保持原位，只追加未覆盖工作；自动移动旧块和最小扰动重排属于下一阶段。

## 使用流程

1. 在“计划 → 学习时间”确认每周可学习窗口与临时禁排；在事项详情确认剩余工作量、最早开始和必要的截止口径。
2. 点“生成计划”，选择未来7/14/28天、开始前预留时间、建议拆分长度和任务。窗口内有明确截止的任务纳入全部未覆盖剩余量；窗口外截止或无确定截止的任务填写本轮目标分钟。本轮目标包含窗口内已有覆盖。
3. 核对新增时间块、已有覆盖、本轮未安排量和后续工作量。生成候选本身不写入正式个人计划，点击“确认应用”后才保存。
4. 完整方案排不下时，可主动查看可安排部分；部分方案显示剩余未安排分钟，勾选明确接受后才能应用。失败、超时、分块限制各有独立状态，不把一次求解失败解释为普遍无解。
5. “计划”与“今日”展示个人安排。计划列表可锁定、解锁、取消、查看关联任务，以及撤销最近应用且尚未被修改、锁定或开始的整批方案。排过的时间不自动视为完成，仍需更新任务进度。

## 求解口径与边界

学校课程、已确认考试和需要预留的完整考试区间作为固定占用；学习窗口扣除这些占用、临时禁排和全部有效已有个人计划后，得到新块的可用域。窗口内有需预留但缺少完整时间的考试时，先要求核对。已有个人计划不符合当前约束时也暂停生成，列出冲突供处理。

时间使用整数分钟：可用开始向上取整、结束向下取整，保证不跨越真实边界。任务不能早于最早开始，也不能晚于已确认截止。可拆分任务默认45分钟，界面可选15/30/45/60/90分钟；尾段不足15分钟时并入前段，总工作不足15分钟时保留原长度。不可拆分任务必须连续安排，不能用多轮目标或保留部分旧块的方式补成多段。

本轮计算分开记录窗口内已有覆盖、窗口外覆盖、本轮新增、本轮未安排和以后再安排的工作。过期块不抵扣剩余工作。已有未来覆盖超过重新估计的剩余量时，要求用户核对取消哪些块，避免静默缩减或重复安排。

CP-SAT使用区间变量与不重叠约束；完整方案以较早安排紧张/高优先级任务为目标。明确请求部分方案时优先保留加权工作量，再在预算内优化较早安排。每请求预算10秒，最多100个任务，已有未来块与新增块合计最多300个；构造块列表前检查上限。每个API进程最多同时求解2个请求，同一用户最多1个，繁忙时返回明确提示。采用同步限时接口和持久化候选，本批没有长期作业队列。

求解后另行验证区间、工作量、不可拆分、相互重叠和覆盖账目。返回实际求解状态与版本；只有得到相应最优状态才标为最优，含义限定为本轮目标与约束。尚未优化连续学习后的休息、跨任务切换成本或全局最小扰动。

实现依据：[Google OR-Tools调度区间与不重叠约束](https://developers.google.com/optimization/scheduling/job_shop)、[CP-SAT状态说明](https://developers.google.com/optimization/cp/cp_solver)。锁定版本为`ortools==9.15.6755`，运行结果同时记录实际库版本。

## 确认、一致性和关联变更

迁移`0006_plan_proposals`新增候选、个人时间块和操作历史，按用户、学期和事项建立关联。生成保留输入快照指纹；计算完成后检查学期修订号。应用时再次检查所有权、候选版本、学期修订、时间有效期和最新约束，并在学期行锁内落库。同一已应用候选重试返回原回执，不重复插入；其他账号不可读取或确认。

候选有效期覆盖新增开始时刻与所选任务已有覆盖变化的时间边界。核对期间已有覆盖减少时，旧方案不能沿用较低的未安排量。Flutter获知更高学期修订后立即禁用旧候选，服务端仍执行最终检查。撤销只取消符合条件的最近一轮新块，不回滚课程或任务进度；取消和锁定均保留审计记录。

进度更新、完成和取消事项先预览真实关联的未来计划，用户选择取消哪些块；锁定块额外要求明确同意解锁并取消。调整学习时间会显示不再符合设置的计划数量，明确确认后保存新设置，原计划位置保留并标注冲突。修改任务剩余量不能直接降到保留计划覆盖量以下。

余量算法已接入真实个人计划：扣除其他任务有效占用，自己的覆盖不重复扣；共同需求窗口内的任务计划也不能再次当成外部占用。失效块独立提示。08中的“尚无计划块、其他占用为0”是上一批历史状态，本批已替换该前提。列表显示未来及近7天的未取消记录，完整取消历史界面尚未实现。
