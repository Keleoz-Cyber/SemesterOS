# 云端手机测试部署

2026-09-20，用户指定SSH主机`keleoz-tencent`，确认使用现有域名路径与空云端数据库。

## 手机使用

- 手机测试包：[下载APK](https://keleoz.com/semesteros/phone.apk)。支持ARM64和ARM32，Android 7或以上；当前为调试签名测试包，不是商店发布包。
- API入口：`https://keleoz.com/semesteros`，健康检查为`/health`。
- 手机重新注册学期OS账号。密码支持8—128位，注册、登录与恢复校验一致。恢复码请自行保存。
- 未迁移电脑上的任何私人账号、课表、事项或原图录音。验证使用独立合成账号；新注册账号没有预置学期。
- 手机不需要和电脑处于同一网络，电脑关机后云端服务仍可使用。

## 服务器布局

独立项目：`/opt/semesteros`。当前源码在`releases/phone-test-20260920`，`current`指向该目录。私有配置为`.env`（600权限），模型在`models`（容器只读），备份在`backups`。

`deploy/compose.cloud.yaml`创建`semesteros-cloud`项目，数据库和媒体分别使用独立命名卷。API只在服务器回环地址8871提供服务，数据库不映射宿主端口。API、识别worker和数据库配置自动重启及资源限制；API与worker用非root用户运行。

已有博客继续运行在原端口8080。Nginx只为其现有HTTPS站点增加`/semesteros`路径，配置片段是`/etc/nginx/snippets/semesteros-location.conf`。安装前保存原站点配置，检查成功后reload，不替换博客根路由。API响应设置private/no-store；模型密钥不进入APK或Git。

## 查看和更新

```bash
ssh keleoz-tencent
cd /opt/semesteros/current
sudo docker compose --env-file /opt/semesteros/.env -f deploy/compose.cloud.yaml ps
sudo docker compose --env-file /opt/semesteros/.env -f deploy/compose.cloud.yaml logs --tail=100 api worker
```

更新前先备份，并将新源码放入新的`releases`目录。构建新的镜像标签，执行迁移后启动API和worker，通过健康与业务检查后再切换`current`。不使用`down -v`，它会删除云端数据卷。版本回退需要保留旧镜像，并确认数据库迁移是否向后兼容；首次上线前的Nginx备份位于`backups/nginx-keleoz-*.conf`。

## 手动备份

```bash
sudo bash /opt/semesteros/current/deploy/backup_cloud.sh
```

脚本短暂停止本项目的API和worker，备份数据库、媒体和私有配置，结束时恢复服务，不停止博客。备份含私人数据和密钥，目录权限700，文件按077掩码创建，不发布到下载路径。尚未设置自动备份或跨服务器灾备。

## 构建手机包

在仓库`apps/mobile`目录执行（PowerShell）：

```powershell
. '..\..\scripts\android-device.ps1'
Set-SemesterGradleJava
flutter --no-version-check build apk --debug --no-pub --target-platform android-arm,android-arm64 --dart-define=API_BASE_URL=https://keleoz.com/semesteros --target lib/main.dart
```

本地交付文件为`output/apk/SemesterOS-0.1.0-cloud-phone-debug.apk`，校验信息在同目录JSON。与旧的模拟器本机后端包分开保存。公网APK下载支持分段请求，方便手机断点续传。
