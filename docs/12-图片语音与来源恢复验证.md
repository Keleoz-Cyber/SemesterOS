# 第七批：图片通知、语音记录与来源恢复

日期：2026-09-20。分支：`codex/android-foundation`。目标流程为“选图/录音 → 私有来源 → 本地识别 → 对照校对 → DeepSeek结构化解析 → 用户确认”。本批不新增第五个Tab，入口在“＋记录”。

## 使用流程

- 图片通知：从系统图片选择器选择一张通知，预览后上传识别；支持JPEG/PNG/WebP，输入最多10MB、2000万像素，不接受动画图。服务端按文件内容验证格式、处理方向并去除EXIF元数据，保存规范化PNG。
- 语音记录：用户主动开启麦克风权限后录音，保存16kHz单声道16位PCM WAV。上限120秒/20MB，界面提前在约119秒发起停止以留收尾时间；进入后台也停止。录音可在本机回放，上传后可从来源页回放。
- 识别后保留机器原文与可编辑校对稿。先核对文字、数字及原消息时间，再发送校对文字和当前学期课程候选给DeepSeek；原媒体不发送给DeepSeek。
- 模型结果仍走原有新增事项核对页。调课等现实变化意图转入变化中心，传递原消息时间和来源关联，仍需独立确认。多条事项应分开核对，不承诺一次读完整张课表或考试表。
- 拒绝录音权限、识别失败或模型不可用时可手工填写。没有成功上传来源时，手工入口明确说明原文件不会关联到该事项。
- 事项详情可查看关联原图/原录音、识别文字和最新校对稿。删除服务端原文件后保留文字、历史及已保存事项，并显示原文件已删除。

## 本地识别方案

图像识别使用`RapidOCR 3.9.2`、`onnxruntime 1.30.0`，本机默认模型为PP-OCRv6小型检测/识别与方向分类。使用引擎返回的文本行，不依赖图片文件名，不将置信分数当作时间事实。[RapidOCR使用与输出说明](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/usage/)

语音识别使用`sherpa-onnx 1.13.8`运行SenseVoice int8模型，按官方发布包`2024-07-17`获取，输出文本并去除控制标记，不使用情绪等标签判断用户状态。模型与运行库版本写入识别元数据。[官方模型与Python接入资料](https://k2-fsa.github.io/sherpa/onnx/sense-voice/pretrained.html)

二者在API主机的独立CPU进程执行，不需要新增商用服务密钥。语音模型下载脚本为`scripts/setup_media_models.py`，从官方发布地址获取、检查压缩包成员路径及类型，并核对已验证模型SHA-256。模型文件和发布包位于`.local-data/models`，不进入Git或APK。

Flutter使用图片选择、录音及回放插件。Android录音请求按用户动作触发；图库使用系统选择器。WAV录制能力依据插件接口，具体手机仍需实测。[record插件说明](https://pub.dev/packages/record/versions/6.1.2)、[image_picker说明](https://pub.dev/packages/image_picker/versions/1.2.0)

## 来源、作业与取消

新增迁移`0008_media_sources`：来源记录归属用户和学期，保存类型、大小、随机存储键、上传摘要、版本、识别状态、机器原文、校对稿、参照时间及识别元数据。上传幂等键按用户/学期隔离，同键不同文件拒绝。内容读取经过身份校验；API不暴露磁盘路径。文件存入私有`.local-data/media`，不按用户文件名构造路径。

识别状态为`uploaded → queued → running → recognized/failed`，取消为`cancelled`。数据库保存队列、执行租约及尝试次数，独立worker通过行锁领取；默认租约5分钟，异常中断可重新领取，最多3次后显示失败供用户明确重试。API默认管理一个worker，也支持`MEDIA_WORKER_MODE=external`由部署独立管理。

取消会推进来源版本并清除租约。底层已开始的CPU推理不保证立即停止，但旧租约或旧版本结果无法发布。来源被修正、取消或删除后，迟到的文字模型结果也不能生成有效候选；已经解析但尚未确认的旧候选会在事项创建时再次检查来源版本。取消识别不会删除已经确认的事项。

文件大小、图片像素和音频参数在持久化前检查；无可用文本、输出过长、缺少模型等情况显示明确失败，原文件仍供核对。每用户最多保留500份未删除原文件、合计1GB，近期列表显示50份，关联事项仍可直接访问其来源。规范化PNG有额外30MB存储上限，避免重编码后无限膨胀。

## 草稿与本机文件

每个账号/学期分别保留最近一份文字草稿与媒体草稿，包含校对文字、消息时间、本机文件或服务端来源、上传标识及未保存状态。图库进程被回收时，仅在匹配当前账号草稿的待选择标记下恢复丢失结果；新选择前清理旧选择器结果，防止账号切换后混入旧文件。

草稿写入按存储实例串行；跨重启恢复，不将某个测试/页面的异步队列绑定到所有存储。只改原消息时间也标记未保存。服务器出现新版本时保留本机稿并提示核对，不能自动覆盖；切换来源时先尝试保存，失败后需明确选择是否放弃本机稿。

保存响应绑定来源ID和操作序号，取消或切换后不能将A的回执写到B。上传失败重试复用标识；识别请求出错后重新查询状态，避免误判已接收的作业。退出账号清除本机草稿与账号私有副本；录音在接管成功后清理原临时WAV，回放临时文件在播放器释放后清理。正式服务端来源不会因退出账号自动删除。

- Flutter完整回归68项通过，新增7项媒体/草稿测试：无录音和上传也可手工填写、草稿重建与旧账号写入拦截、文字/参照时间恢复、只改消息时间、取消后的旧保存回执、拒绝权限和文字草稿恢复。实际图片预览另通过合成PNG组件渲染检查。
- 真实本地API联调两种来源、12项检查通过。图片为程序生成通知；音频由Windows中文TTS合成，没有录取真实环境声音。RapidOCR读出“9月25日23:59前交Java实验报告、预计3小时”；SenseVoice转写出相同日期/时刻/工作量；DeepSeek两次均解析为23:59截止和180分钟，经显式确认后才落事项，保留来源与识别元数据。
- 报告`output/verification/media-api.json`记录了本机两次识别耗时（本次约2828ms/1063ms）。这是限定合成样例与单次耗时，不作为泛化准确率、真人语音表现或p95指标。
- 合成素材由`scripts/create_media_fixtures.ps1`生成（需要Windows中文Huihui音色和微软雅黑）；`scripts/verify_media_api.py`运行真实API/OCR/ASR/DeepSeek闭环。组件渲染在`output/verification/media-ui`，不冒充原生录音验收。
- 只读审查发现并修复来源切换后的迟到保存回执、只改消息时间未保留、连续录音残留临时文件；复查补充候选确认前来源版本检查、账号切换回放停止及播放器释放后的文件清理。
- Node教务读取3项通过；`pip check`通过；Compose配置解析通过。完整容器镜像构建、物理手机相册/麦克风/音频路由及厂商后台行为未作为本批完成证据。

## 构建与运行

依赖锁在Python/Flutter锁文件。原生媒体插件固定到与Gradle 8.14/JDK 21兼容的版本：image_picker 1.2.0及Android 0.8.13+5、record 6.1.2及Android 1.4.5、just_audio 0.10.5、audio_session 0.2.2。较新的部分插件使用AGP 9，本批未迁移整套构建工具链。项目的HTTPS Maven镜像同时用于插件构建依赖。

`scripts/dev.ps1 -Action Android`会定位本机JDK 21并仅为本次进程设置Gradle安装目录，不修改全局Java/Flutter配置。也可用`SEMESTEROS_JDK_HOME`指定JDK 21。新增原生插件后必须完整重新运行App。

后端环境准备好后运行`services/api/.venv/Scripts/python.exe scripts/setup_media_models.py`；本机模型已就绪。API启动自动拉起worker。Compose增加私有媒体卷和只读模型目录，Docker路径与本地仓库路径分别适配；备份需同时包含数据库和媒体目录。

静态分析无问题，Android debug构建通过，已核对媒体入口、原生插件及录音权限。导出仍为`lib/main.dart`入口、x86_64模拟器调试包，位于`output/apk/SemesterOS-0.1.0-debug.apk`，附SHA-256和源码提交记录。本批未替用户安装新包；真人麦克风录制、系统图库和回放需装包后验收。
