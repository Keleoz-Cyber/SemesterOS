# App用户文案优化

日期：2026-09-20。本轮集中处理用户可见文案，不增加演示功能。

## 调整范围

录入、图片与录音、自然语言修改、事项与提醒、个人计划、风险说明、课程考试、学期设置和错误提示。

- App中的模型品牌统一改为“AI”；技术配置、模型标识及开发文档保留真实名称，保证现有服务连接正常。
- 以用户行动命名按钮，例如“让AI整理”“查看修改前后”“确认保存计划”“放弃这次修改”。
- 将“候选、覆盖、口径、禁排、块长、求解约束”等内部术语改为具体解释。保留“计划余量”，并说明计算依据。
- 长说明从输入框标签移到可换行帮助文字；修改预览的分钟显示为小时/分钟，布尔值显示为“可以分次完成/需要一次完成”。
- 保留确认、放弃、锁定计划取消、冲突和未安排工作等关键提示；AI内容发送说明改为普通中文。
- 统一错误显示：保留可操作的中文原因，不直接展示插件异常、英文内部错误和Exception前缀；区分网络不通、等待超时和服务暂不可用。
- 服务端返回的错误、计划解释及AI补充问题也采用面向用户的表达，提示词版本递增，数据合同与模型供应商配置不变。
- 修正“事项开始时”不适用于任务截止提醒，以及备用页面仍称规划未开放等不准确文案。

## 后续文案原则

按钮说明点击后会发生什么。提示优先解释发生了什么、用户下一步能做什么。技术细节留在日志与开发文档。不能为简短而删掉实际影响，也不能将“生成建议”说成“已经保存”。

本轮通过100项后端测试、76项Flutter测试与静态分析；另用真实AI验证4类新增录入和12项修改/规划断言。最后的文案修整继续使用对应页面测试检查。

页面渲染截图位于本机忽略目录`output/verification/user-copy/`，使用合成数据，包括录入、修改预览、计划生成、提醒、余量说明和大字体页面。它们是Flutter渲染结果，不是真机截图。本轮不将文案优化等同于其他App问题全部解决。
