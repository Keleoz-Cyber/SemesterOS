# 第六批：课程事务、考试中心与学期时间轴

日期：2026-09-20。分支：`codex/android-foundation`。本批聚合已有事实和算法结果，补齐按课程、考试和整学期查看的入口；没有复制一套日程或引入演示专用逻辑。

## 使用入口

- 点击“今日/课表”中的已导入课程 → 课程事务。显示课程与教师、待办任务、关联考试、已完成/取消任务、有效课次及已确认的调停课记录；点击事项进入详情或考试中心。新增作业/考试/任务会预选当前课程。
- “学期” → 学期时间轴，课程列表和考试中心也在这里。原学期创建、切换、教务导入和手工补课表保留在“管理学期与课表”。
- “学期 → 考试中心”或考试事项详情 → 考试与复习。考试按已知时间排序，周次和未知时间继续保留原精度；可查看已取消考试及其仍保留的复习任务。
- “设置 / 关联复习任务”可自定义分钟数，或主动选轻量2小时、标准4小时、充分8小时作为建议。没有默认选中工作量；这些预设不是对个人能力或真实需求的预测。已有未完成复习时进入其详情调整目标与进度，不反复创建重复任务。
- “考试改期 / 确认正式安排”进入时间精度、确定性、地点和依据核对。普通考试编辑也转入影响预览，保存前核对考试、提醒、复习截止和个人块冲突。

## 数据关联与计算口径

课程查询依赖用户、学期和课程ID；学校提供相同`source_id`时才归组多条授课模式。没有该标识时不按同名课程猜测关联。没有明确课程关联的任务不会出现在某门课的事务页；历史和原文仍从相关事项详情读取。新增的无课程关联固定活动或补课，继续从现实变化记录查看。

复习任务通过服务端写入`review_exam_id`显式关联考试，复用现有StudyItem、进度、排程和提醒流程；旧客户端编辑时保留该关系。一次考试默认只允许一条活跃复习任务，已完成或取消的关联记录保留。关联已有任务不同时覆盖其工作量与截止；新建时明确选择“按正式考试开始截止 / 自定义截止 / 待确认”，最早开始也需明确选择。

考试中心分别展示剩余工作、有效计划覆盖、未覆盖工作和已确认完成任务数。未建立复习时显示“复习目标尚未设置”，不把缺少目标描述成复习已完成。存在未知剩余估计时保持未知，不以0替代。考试取消不自动完成或取消个人复习任务，而是提示用户处理；考试提前后若复习截止晚于考试，也明确提示核对。

时间轴按北京时间周边界归集具体时刻、仅日期、学期周次和跨周日期范围。只有第14周的考试出现在第14周，仍显示“具体日期待确认”，不伪造周一考试。未知日期和完全位于学期外的事项单列。日期范围可跨多个周展示同一事项，不重复计算其任务需求。周日“当天结束前”截止仍计入周日所在周，不因底层锚点为次周零点而漏掉。

每周展示从当前时刻起扣除真实固定占用与禁排后的可学习分钟，以及有效个人块占用。本周截止的已知剩余工作单独展示；它可能提前在前几周完成，因此不计算“本周需求减本周容量”作为不可行结论。有效个人计划使用率达到80%，或该周含既有算法判定的高风险事项时提示负荷；80%只是可解释的工程提示阈值。学习时间未设置或需预留考试时间缺失时，容量保持待确认；过去的周标为历史。跨任务可行性继续使用原有余量/排程算法。

## 考试改期一致性

预览只读，显示考试前后信息、提醒重算结果、关联复习截止（保持或同步）、相关复习提醒以及受影响个人块。同步活跃复习截止是独立选项，只有正式明确的考试开始时刻才允许同步；不改任务剩余工作量，不移动时间块。

确认检查考试版本、学期修订和预览指纹。指纹覆盖目标考试数据、请求内容以及考试/关联复习的提醒ID、版本和规则；仅修改提醒不增加学期修订的既有机制仍可保留，同时阻止核对期间新加或修改提醒后沿用旧预览。固定冲突需明确确认。确认后记录ItemRevision、重算相对提醒并更新相应规则版本，重复请求用原幂等键返回同一回执。

服务端一次返回考试与所有同步复习任务的完整确认回执；客户端先批量更新本机事项/提醒，再拉取最新清单。这样POST成功但后续GET断网时，也会撤销旧时间的通知。批处理保留账号代次和旧响应覆盖保护；不能把上一账号的回执应用到新账号。

新页面查询在同一学期修订下生成事实与风险投影。已知修订变化、查询失败、离线或分析过期时不继续显示旧精确负荷/余量；支持手动刷新与45秒定期刷新。切换账号或学期后，旧页面提示返回重开。

- Flutter完整回归61项通过：新增5项中心页面流程/布局测试及1项确认后断网的批量提醒回执回归。覆盖未明确工作量不提交、暂定考试没有继承精确截止选项、过期修订禁止确认、大字体时间轴，以及复习覆盖与完成分开显示。
- 真实本机API合成联调12项通过，脚本`scripts/verify_centers_api.py`。合成课程关联正式考试，创建180分钟复习并安排；改期预览不落库，期间新增提醒使旧预览失效；重新核对后确认，考试及复习截止/提醒更新、工作量保持、原个人块保持并显示新冲突，课程与时间轴使用同一修订。未访问真实学生账号，未调用模型。
- 报告：`output/verification/centers-api.json`。合成UI渲染：`output/verification/centers-ui/`，已查看课程事务、考试中心、改期预览和大字体时间轴。本批没有将新包安装到用户模拟器，也没有宣称完成物理手机验证。
- 只读审查发现并修复确认后断网沿用旧提醒、周日日末截止漏算，以及核对期间提醒变动未使预览失效；另修复预览after中的旧锚点/提醒不一致。问题均补了回归。

Flutter静态分析无问题，Android debug构建通过，APK内已核对中心入口与正式应用入口，未混入通知测试入口；教务读取Node回归3项通过。APK为`lib/main.dart`、x86_64模拟器调试包，导出至`output/apk/SemesterOS-0.1.0-debug.apk`并附SHA-256及源码提交。沿用本机API与PostgreSQL，没有新增数据库迁移或修改已有用户数据。

## 保留边界

本批复用已有数据模型，尚无复习学习内容、知识点或成绩预测；不自动为考试估计工作量，不将日历覆盖作为学习完成。课程归组缺少学校标识时仍可能显示多条独立授课记录，后续可加明确的人工合并流程。时间轴不是学期复盘，也未实现拖拽排程、完整离线写入或大型数据分页。图片/语音录入、自然语言修改个人任务/提醒、匿名比赛演示模式和真机发布验收仍待后续开发。
