# 第三批：可学习时间与计划余量

日期：2026-09-20。分支：`codex/android-foundation`。本批实现02第8节的容量分析与前置数据，不包含OR-Tools自动排程。

## 使用入口

- 计划页“学习时间”：每周多段可学习时间、临时禁排，先核对前后设置再保存。使用北京时间；跨天学习分两天设置，结束00:00明确解释为当天24:00。相邻/重叠学习窗口归并，禁排按并集扣除。
- 事项编辑：考试支持明确结束日期与时刻；暂定考试可选择是否预留。任务的更多设置提供“最早开始待确认 / 从现在起 / 指定时间”。旧记录不自动补齐这些事实。
- 事项详情“更新进度”：预览旧剩余、新剩余和可空的实际投入；确认后记历史。实际用时不自动从剩余中扣除。剩余0只有明确确认完成才停用提醒；恢复这种已完成事项后，剩余耗时重新待确认。
- 任务卡及“计划余量依据”：单项余量、共同窗口的需求/容量/缺口、最长连续空档和需补充的信息。共享缺口优先显示，即使该任务单独计算仍有正余量。

## 计算口径

仅在用户确认的每周学习窗口中，从当前时刻或任务最早开始（取较晚）计算到已确认截止；分析范围到学期结束。只有日期的任务须由用户确认当天结束口径。课程按原始周次、星期和不连续节次展开；完整考试、暂定预留及临时禁排按区间并集合并，避免重复扣除。

单任务余量等于该窗口内可用容量减预计剩余工作量。本批尚没有个人计划块，`other_plan_minutes=0`；其他未安排任务仍进入整体容量检查，不会因此消失。多个任务按不同最早开始/截止形成子窗口，共享一份可用容量；报告最大的已发现缺口，不叠加相互重叠窗口的缺口。

当前以完整分钟保守估算；工作量是用户的估计，不是保证完成的真实耗时。总容量足够不证明存在全体任务排程。不可拆分任务若连一个足够长的连续空档都没有，显示明确的连续时段问题；未运行求解器时不宣称已经找到可行方案。

未设置学习时间、未知耗时/最早开始、未确认截止、缺少考试结束、超出学期范围等，保留缺失原因，不补造精确余量或无条件低风险。其他任务信息未齐时，已知任务可显示自己的单项计算，但整体等级保持未确定。暂定考试关闭预留后不扣时间，仍提示不确定安排。考试时间未知时，已知占用下计算的容量只可作为上界；有明确缺口时显示“最多可用”，不会伪装精确容量。

本批最多精确分析200项活跃任务；超限返回明确未完成状态，不截取前200项假装整体分析完成。固定冲突数量完整返回，详情仅展示前30处并明确标注。规则标识为`risk-v1`，这是待校准的工程规则，不是学业表现预测模型。

## 数据与一致性

新增迁移`0005_capacity_inputs`：学习设置、设置变更历史、进度记录，均按用户和学期/事项关联。预览只读；确认时检查事项/设置版本和学期修订号，并使用幂等记录保护重试。已有课表及事项不重建或删除。

学习设置、工作量或日程改变均更新学期修订号。风险接口在短事务内取得一致快照，释放数据库锁后计算。返回修订号、计算时间与有效期。Flutter按账号、学期、事项版本和修订号校验结果；重新导入课程或课表同步发现新修订时立即作废旧分析，避免等待定时刷新期间仍显示旧低风险值。前台每45秒刷新，有效期1分钟；离线不展示旧精确余量。

旧客户端编辑时，省略的新规划字段会保留；显式清除考试结束时间则恢复为未知。原始来源和解析证据保持不可变，用户修正另记依据。文字模型增加可选考试结束字段，只有原文明确说明才提取；任务最早开始由用户确认。

## 验证结果

- PostgreSQL：41项通过，使用独立随机测试schema；包括原有账号/导入/提醒、新设置预览、跨用户拒绝、版本与幂等、进度完成撤销提醒、旧客户端字段保留、显式清除及风险计算。测试依赖仍有既有的两条弃用提示。
- 计算测试覆盖共享容量超载、固定占用并集、已过去时间不抵扣工作、最早开始子窗口、未知考试、不可拆分空档、过期任务、学期范围、暂定截止，以及100组固定种子的独立分钟集合对照。
- Flutter：47项通过；静态分析无问题。覆盖新学习设置的二次确认、任务进度明确完成、考试结束保存/清除、最早开始选择、共享缺口优先级、旧课程修订立即失效、时间过期隐藏数字和大字体布局。
- 教务读取Node回归：3项通过。
- 真实本地API合成联调：两任务共需5小时、共享4小时得到缺口60分钟；加入1小时考试得到120分钟；确认一项任务剩余变为60分钟后得到30分钟；添加与考试重叠30分钟的禁排后得到60分钟。报告为`output/verification/capacity-api.json`。所有值来自API实际计算，无真实学生数据。
- DeepSeek真实合成样例4项通过，包含新增的明确考试开始/结束（2小时区间）。这是限定样例的接入回归，不作为泛化准确率指标。
- 独立只读审查完成：修正任务确定性未进入完整性检查、导入新课表后旧风险仍可用、容量上界在概况被标成精确值等问题，并补充回归。

`output/verification/capacity-ui/`为合成数据的Flutter组件渲染，已查看学习时间、余量依据、进度预览和大字体页面。它不是本批Android实拍；既有原生提醒投递验证见07。
