# 学校课表导入、图片和录音

这份说明介绍目前支持的接入方式、使用步骤和常见问题。学校网页负责登录，拾日负责读取课表并让你核对；图片和录音先转成文字，再由助手整理。

## 学校课表导入

目前有两个学校适配器，定义在 `apps/mobile/lib/features/import/school_adapters.dart`。

| 学校 | 操作位置 | 当前处理方式 |
| --- | --- | --- |
| 河南工业大学 | 登录后进入“信息查询 → 个人课表查询” | 在已登录网页中读取所选学期的课表，并预填10节作息时间；核对后与课程一起保存。 |
| 黑龙江大学 | 登录本科教务，打开个人课表，选择要导入的学期 | 读取页面中的课程和备注；根据可取得的节次信息补充时间，解析考试等附加内容。 |

支持适配器表示项目已有相应读取代码，不等于学校今后的每次网页更新都能兼容。其他学校可以使用手工录入，目前没有通用的“任意学校一键导入”。

### 操作步骤

1. 先创建学期，并核对第一周周一和节次时间。
2. 进入导入页面，选择学校，在内置网页中自行登录。
3. 打开个人课表，选择正确学期，再点“读取当前学期课表”。
4. 在核对页检查课程名称、上课周次、星期、节次和地点。网页提供的学期信息、解析提醒和附加事项也会显示出来。
5. 核对后确认导入。取消核对不会修改学校的课表。

读取只在允许的学校课表页面进行。一次读取有临时校验值，页面跳转或读取超时后旧结果不再接收。默认读取超时为 25 秒。

### 登录和浏览器提示

教务账号密码在学校网页中输入。项目的读取脚本获取课表数据，不把登录表单、密码或 Cookie 作为导入结果交给拾日后端。学校本身仍会按自己的登录流程处理凭据。

黑龙江大学页面对移动浏览器存在兼容限制，App 会保留系统 WebView 的真实 Chromium 版本，使用桌面浏览器标识和兼容设置打开。它不会把老版本号冒充成新版本，也不会关闭学校网页脚本。若提示 WebView 不支持，先更新 Android System WebView 再试。

退出导入时会清理学校 Cookie、网页存储和缓存，并移除读取桥接。清理失败会提示重试，不应把“退出页面”写成绝对保证清理成功。

### 网络边界

跳转只允许适配器中登记的来源，匹配协议、主机和端口。可升级的 HTTP 地址先改为 HTTPS；不安全的登录路径会跳回已配置的登录入口。陌生地址和反复跳转会被拦住，提示只显示来源地址，不显示票据或查询参数。

黑龙江大学现有课表来源包含 `http://xsxk.hlju.edu.cn`，登录入口使用 HTTPS。这是当前学校站点的兼容范围，不能把整个导入过程描述成端到端全部 HTTPS。

### 常见问题

- **读取不到课程**：先确认已经进入个人课表查询页，而不是登录页、首页或选课页；再次查询所需学期后读取。
- **登录失效**：刷新登录页并重新登录。登录表单提交后，App 会尽量以新的页面请求刷新，避免重复提交旧表单。
- **周次、节次不对**：在导入核对页停下来检查。没有可靠结束时间的信息应保留缺失，不随意补齐。
- **学校网页改版或不可用**：可以先手工录入。新增适配应先准备脱敏页面样本，再增加适配器、读取脚本和解析回归用例。

课程导入只修改拾日中的个人记录，不会向学校教务系统提交选课、调课、请假或成绩变更。

## 图片通知

助手可以选择一张或多张通知截图。多张图片作为同一份通知按顺序识别，文字相邻位置完全一致的重复行会合并；不同通知建议分开发送，便于检查日期和任务归属。

服务端使用 RapidOCR 识别图片文字。图片先校正方向、转成干净的 PNG，再进入识别队列；EXIF 等原始元数据会去掉。

| 项目 | 当前限制 |
| --- | --- |
| 单张图片格式 | JPEG、PNG、WebP，单帧图片 |
| 单张文件大小 | 上传原文件最多 10 MB |
| 单张尺寸 | 最多 2000 万像素 |
| 一次助手图片组 | 原文件合计最多 60 MB；解码后的合计内容最多 120 MB |
| 来源文件存储 | 每个账号未删除原文件的来源最多 500 份、合计最多 1 GiB |

识别完成后仍要核对文字，特别是日期、钟点、教室和数字。OCR 的识别分数是文字识别信息，不代表通知已经核实。图片上传成功也不代表日程已保存。

## 录音

长按麦克风开始录音，松开后交给助手处理；取消手势、权限未开启或录音时离开前台，会停止或取消当前录音。没有麦克风权限时可以改用文字。

App 录制 16 kHz、单声道、16 位 PCM WAV，最长 120 秒。服务端录音文件上限为 20 MB，只接受符合上述格式的 WAV。当前转写使用 SenseVoice 的本地 ONNX 模型，通过 sherpa-onnx 在 CPU 上运行。模型缺失、转写失败或没有可用文字时应提示重试，不会凭空生成通知内容。

图片和录音识别需要部署识别依赖、模型和媒体工作进程。文字助手可用，并不证明媒体识别环境也已准备好。本说明依据实现代码，不把模拟器文字流程的结果当成图片、录音或真机提醒的测试结果。

## 原文件、识别文字和助手保存结果

这三部分是分开的：

1. 上传得到通知来源和原文件。
2. 识别得到文字，可以查看来源、校正文字或重试识别。
3. 助手根据文字提出任务、日程或修改方案，按当前预览和确认流程保存。

修改识别文字需要最新版本；识别正在运行时应先取消再改。原文件删除后不能再次识别，但已有文字和历史记录保留。删除对话也不会把已保存的日程一起删除。删除整个学期会清理该学期关联内容。

来源接口只允许当前账号访问自己的内容。原文件响应禁用缓存；应用不会用一个账号的来源文件为另一个账号提供内容。

## 剪贴板和系统分享

App 在前台、当前页面可见且键盘未打开时检查剪贴板。它用本地文字规则判断是否像通知或日程，例如出现时间、活动、行动要求或截止提示。密码、代码、单独的链接等会尽量排除。

这个判断不调用模型 API，不保存剪贴板原文，也不自动上传。只有你点了导入，文字才带入助手。规则只是提示，可能漏掉简短通知或误判；没有提示时仍可以手工粘贴。

Android 系统分享支持文字和图片，也支持选中文字后交给拾日处理。分享内容会作为输入草稿，登录并选择学期后再继续处理。
