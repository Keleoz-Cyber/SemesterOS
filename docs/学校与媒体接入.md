# 学校课表导入、图片和录音

这篇讲现在支持哪几种接入、怎么操作、卡住了先看哪里。学校网页负责登录，拾日负责把课表读出来给你核对；图片和录音都是先转成文字，再交给助手整理。这两类东西的边界不一样，别混着理解。

## 学校课表导入

目前只有两个适配器，都在 `apps/mobile/lib/features/import/school_adapters.dart` 里。

| 学校 | 在哪操作 | 怎么读 |
| --- | --- | --- |
| 河南工业大学 | 登录后进“信息查询 → 个人课表查询” | 在已登录的网页里读当前学期课表，顺带预填 10 节作息；核对后跟课程一起保存 |
| 黑龙江大学 | 登录本科教务，打开个人课表，选好学期 | 读页面上的课程和备注；按能拿到的节次信息补时间，考试这类附加内容也解析 |

“有适配器”只说明项目里有对应的读取代码，不代表学校哪天改版了还能用。别的学校走手工录入，现在没有那种“随便哪个学校一键导入”的东西。

### 步骤

1. 先建学期，把第一周周一和节次时间对一遍。
2. 进导入页，选学校，在弹出的内置网页里自己登录。
3. 打开个人课表，选对学期，点“读取当前学期课表”。
4. 在核对页看课程名、周次、星期、节次、地点。网页给的学期信息、解析提醒、附加事项也会列出来。
5. 核对完确认导入。取消核对不会去动学校的课表。

读取只在适配器登记的课表页面上进行。一次读取带一个临时校验值，页面跳走了或者读超时了，旧结果就不收了。默认超时 25 秒。

### 登录和浏览器

账号密码是在学校网页里输的。项目的读取脚本只拿课表数据，不把登录表单、密码、Cookie 当成导入结果交给拾日后端。当然，学校那边还是按它自己的流程处理凭据，这部分不归我们管。

黑龙江大学的页面对手机浏览器有限制。App 的处理是保留系统 WebView 真实的 Chromium 版本，用桌面浏览器标识加兼容设置去打开。它不会把老版本号冒充成新版本，也不会把学校网页的脚本关掉。要是提示 WebView 不支持，先去更新 Android System WebView 再试。

退出导入时会清学校 Cookie、网页存储、缓存，并把读取桥接拆掉。清理失败会提示重试——所以“退出页面”不能写成“保证清理干净”。

### 网络边界

跳转只允许去适配器里登记的来源，协议、主机、端口三项都要对上。能升级的 HTTP 地址先改成 HTTPS；不安全的登录路径会跳回配置好的登录入口。陌生地址和来回跳转会被拦下，提示里只显示来源地址，不带票据和查询参数。

黑龙江大学现在的课表来源里有 `http://xsxk.hlju.edu.cn`，登录入口走的是 HTTPS。这是学校站点当前的兼容范围，所以整个导入过程不是端到端全 HTTPS，写材料的时候别这么讲。

### 卡住了看这里

- **读不到课程**：先确认停在个人课表查询页，而不是登录页、首页或选课页；重新查一次所需学期再读。
- **登录失效**：刷新登录页重新登。表单提交后 App 会尽量用新的页面请求刷新，避免把旧表单重复提交一遍。
- **周次节次不对**：在核对页停下来看。没有可靠结束时间的信息就该留空，不要顺手补齐。
- **学校改版或打不开**：先手工录入顶着。要加适配，先弄一份脱敏的页面样本，再写适配器、读取脚本和解析回归用例。

不管导入成什么样，它只改拾日里的个人记录，不会向学校教务提交选课、调课、请假，也不会改成绩。

## 图片通知

助手可以选一张，也可以选好几张截图。多张按顺序当成同一份通知识别，文字相邻且完全一样的重复行会合并掉。不同通知最好分开传，日期和任务归谁更不容易错。

服务端用 RapidOCR。图片先进来处理：校正方向、转成干净的 PNG，然后才进识别队列。EXIF 这些原始元数据会被去掉。

| 项目 | 现在的限制 |
| --- | --- |
| 单张格式 | JPEG、PNG、WebP，单帧 |
| 单张大小 | 上传原文件最多 10 MB |
| 单张尺寸 | 最多 2000 万像素 |
| 一次助手图片组 | 原文件合计最多 60 MB；解码后合计最多 120 MB |
| 来源文件存储 | 每个账号没删原文件的来源最多 500 份，合计最多 1 GiB |

识别出来后还是要核对，特别是日期、钟点、教室和数字。OCR 的识别分数只是“这几个字像不像”，不代表这条通知已经核实过了。图片传上去了也不代表日程存上了。

## 录音

长按麦克风开始录，松开就交给助手；中途做取消手势、没给麦克风权限、或者录的时候 App 退到后台，都会停掉或取消这一次。没权限就打字。

App 录的是 16 kHz、单声道、16 位 PCM 的 WAV，最长 120 秒。服务端收文件上限 20 MB，只认这个格式的 WAV。转写用 SenseVoice 的本地 ONNX 模型，通过 sherpa-onnx 在 CPU 上跑。模型缺了、转写失败、或者转出来没有可用文字，就提示重试，不会凭空编一段通知出来。

图片和录音要能用，得把识别依赖、模型、媒体工作进程都部署好。文字助手能用，并不说明媒体识别也配好了。

## 原文件、识别文字、保存结果

这是三件不同的事：

1. 上传，得到来源和原文件。
2. 识别，得到文字。文字能看来源、能改、能重试。
3. 助手根据文字提任务、日程或修改方案，走当前的预览和确认流程保存。

改识别文字要拿最新版本；识别还在跑就先取消再改。原文件删了就不能再识别，但已经识出来的文字和历史记录都留着。删对话也不会把已保存的日程一起删。删整个学期才会清掉该学期关联的内容。

来源接口只让当前账号看自己的东西。原文件响应禁用了缓存，不会拿 A 账号的文件去喂 B 账号。

## 剪贴板和系统分享

App 在前台、当前页面可见、键盘没弹起来的时候才会去看剪贴板。它用本地文字规则判断像不像通知或日程，比如有没有时间、活动、行动要求、截止提示。密码、验证码、单独一个链接这类东西会尽量排除掉。

这个判断不调模型，不存剪贴板原文，也不会自动上传。只有你点了导入，文字才被带进助手。规则只是提示，短的会漏，也会误判；没提示的时候你照样可以手动粘。

Android 的系统分享支持文字和图片，选中文字分享给拾日也行。分享进来的内容先当草稿，等你登录、选完学期再往下处理。
