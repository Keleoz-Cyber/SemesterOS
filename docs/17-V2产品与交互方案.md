# V2 产品与交互方案

状态：设计提案，可审阅原型；未实现到手机 App。依据为用户首轮反馈与补充定位，见16文档。此次只交付设计，不修改线上数据，不制作比赛演示，不重新命名产品。

## 1 产品定位与取舍

面向大学生的智能日程助手：把临时通知、课程和个人任务放进同一套时间安排，通过一句话查询、记录和调整，帮助用户理解安排变化与采取下一步行动。

完整主线：收到通知 → 理解并关联已有事项 → 核对关键内容 → 与课表合并展示 → 检查影响 → 提出可执行调整 → 记录实际进度并更新建议。

| 方案 | 优点 | 问题 | 决定 |
| --- | --- | --- | --- |
| 日程为主，统一智能入口辅助操作 | 一眼看见安排，复杂操作可自然表达，手工入口仍可用 | 需要把对话结果与页面状态同步 | 推荐，作为本版原型方向 |
| 聊天首页，其他页面作为工具结果 | 自然语言入口突出 | 每次看课程都要找消息，日常浏览效率较低 | 不作为首页 |
| 保留原页面，逐页增加AI按钮 | 短期改动小 | 继续放大入口重复与分类负担 | 不采用 |

Agent是应用的操作入口之一。用户无需聊天也能看课表、改提醒和填事项；用户选择表达需求时，Agent应自行查询上下文并调用能力。统一入口替代操作菜单，不让用户先区分新增、修改、重排。

## 2 页面分工与导航

底部四个目的地建议改为 **今日／日程／计划／学期**。“课表”成为日程中的课程视图；命名为设计选择，等待用户看原型后的反馈。

底部导航上方设置一个紧凑的智能输入条“记录日程，或向AI提问”，包含明确的语音入口。它占据独立布局空间，不能覆盖内容；向下浏览时可以收窄，但保留一个清晰入口。点击后拉起统一输入面板，原页面位置不丢失。四个目的地没有第五个聊天Tab。

| 页面 | 第一屏任务 | 下方内容与深入入口 |
| --- | --- | --- |
| 今日 | 日期、下一项安排、今日课程紧凑列表、最近需要处理的一件事 | 今日个人计划、可配置模块与短建议 |
| 日程 | 紧凑周次选择、课程与其他固定安排的时间网格 | 选中日的完整时间线、截止事项、空档解释 |
| 计划 | 当前要完成的任务与已经分配的时间，冲突或临近截止优先 | 已完成记录、可学习时间设置、方案历史 |
| 学期 | 学期进度与当前周定位、近期重要节点 | 按周负荷概览、考试、课程事务、学期管理 |

### 今日

移除大品牌横幅和独立“课程数量”统计大卡。以时间、标题、地点组成紧凑列表；已结束课程弱化，正在进行和下一项有明确文字标识。课程常见数量3至4次时优先容纳在首屏；小屏、大字号或高密度日程允许滚动，不缩小到难以点击。

紧急事项保留稳定位置，不受用户隐藏模块影响。自定义仅作用于“接下来”区域：近期截止、个人计划、空档建议、近期考试可排序或隐藏，提供恢复默认。课程和紧急事项默认常驻。模块设置进入一次编辑态，不给每块卡片都常驻一个编辑按钮。

### 日程

顶栏“第4周”打开周选择面板，提供明确“回本周”。周次前后切换有方向性动效。周网格与按天查看共享选中日期与已加载数据；点日期进入该日，不突然显示一个类似今日页的整周卡片列表。

课程、一般固定日程、个人计划使用不同边线或标签；颜色不能成为唯一识别方式。截止事项置于当天截止区域，不假装占用一段时间。未知日期事项放在“时间待确认”，不强行塞进某一天。

手势优先级：竖向查看时段；横向仅承担一种动作。在七天需要水平浏览的布局中不同时启用横滑切周，切周使用顶部控件。单日时间线不复刻首页统计与建议。

默认不允许拖动学校课程、考试与确认的固定日程来重排。个人计划可在后续提供拖动预览，但落点须重新核查冲突，不能由日历组件直接保存。

### 计划

默认展示“待完成”和“已安排”的联系，每项任务显示截止、剩余工作量、已经安排多久。缺耗时不妨碍记录；只有安排时间确实需要时才询问。

一个主要动作“安排任务”打开带上下文的智能输入。生成与重排由当前状态和用户需求决定，历史方案为次级入口。未设置可学习时间时只展示一个设置入口；设置后收进页面设置。移除正常状态的“重新计算”，相关变化触发后台分析，异常时提供就地重试。

完成一段计划不能自动认定整个任务完成。明确询问实际完成量，或让用户直接选择“任务已完成”；反馈进入后续分析。

### 学期

以20周可扫读的周带定位进度，选中周显示节点而非展开一长串空按钮。打开默认聚焦当前周；过去空周弱化。考试、截止和现实变化分层展示，暂定节点明确标注。

课程事务、考试清单、学期管理保留，但层级低于节点浏览。无必要不重复刷新；离开后返回保留选中周、滚动位置和已加载内容。负荷数据过期时可以保留事实节点，隐藏失效的计算结论。

### 学校选择

导入入口先展示学校选择与搜索。当前只有河南工业大学标为“可导入”；其他搜索结果不能误导为已适配。找不到学校时给出手工添加及反馈入口。再次导入默认展示上次学校，仍允许切换。教务密码仍只在学校原站输入。

## 3 完整场景及固定验证数据

原型采用独立合成数据，固定北京时间 **2026-09-23周三11:40**，学期第1周周一为2026-08-31，即第4周。原型仅在浏览器内演示状态变化，不连接云端，不调用真实AI、不采集录音。

当天课程：08:00—09:50计算机图形学，10:00—11:50概率论，14:00—15:50软件工程。个人计划“Java实验报告”原在周三17:00—18:00，计划所需1小时，截止周五18:00。周四16:00—17:00是用户明确设置的可学习时段，且无固定安排。

用户输入：“周三17点到18点开组会，会议室6412，帮我调整冲突的学习计划。”

1. 系统按输入时间解释本周三，提取一个固定日程候选；以可点击日期时间与地点展示，不铺满表单。
2. 提示已发现与Java报告计划重叠1小时。主要动作“加入日程”，提醒默认提前30分钟，允许修改。录入事实的确认不附带执行个人重排。
3. 保存组会后，显示“组会已加入，1段个人计划需要调整”。只有用户原话包含调整请求时才继续自动生成方案；仅录入通知时提供“帮我调整”选项。
4. 方案只移动Java报告至周四16:00—17:00，其他安排保持。给出前后差异、理由和“一段，1小时”的影响规模，不声称移动后凭空增加空闲时间。
5. 用户可回复“周四不行”要求重新查询，不重新上传通知。没有其他可行时间时明确展示未安排内容和可选取舍。
6. 点击“应用调整”后执行并核查，日程与计划页同步显示结果，提供撤销。撤销该轮重排只恢复个人计划，不删除已保存的组会，并重新显示原冲突。

原型的验证路径覆盖第1至4及第6步；自由文本会话、其他时间选择、真实通知识别和求解由后续真实实现验证，不把固定交互脚本称为Agent。

## 4 统一智能面板

面板初始展示输入框、图片／语音入口和少量贴近当前页面的建议。手动录入收在次级入口。输入后保留原文，处理状态按事实显示“正在读取日程”“正在检查冲突”“正在生成调整方案”，不显示虚构百分比或内部思维过程。

结果采用可操作卡片：查询给出安排列表与依据；录入给出候选；修改展示差异；重排给出受影响条目；失败指出未完成部分。消息可以引导打开某个日期或事项详情，返回后保留上下文。

### 确认和撤销规则

| 请求 | 默认处理 | 边界 |
| --- | --- | --- |
| 查询日程、分析空档、生成候选 | 直接返回，不请求确认 | 结论绑定当前数据版本与查询范围 |
| 在明确对象的详情里说“提醒改到明天18点” | 可直接保存并给撤销 | 对象唯一、时间明确、没有扩大修改范围；含糊则追问 |
| 从通知提取新增安排 | 一张候选卡确认 | 缺日期可保存为待确认；不得生成虚构时间 |
| 修改固定安排、任务截止、取消事项 | 展示前后变化后确认 | 修改依据、影响范围可查看 |
| 多事项录入或多段计划调整 | 分组预览，一次确认所选组 | 不为每个内部工具步骤弹窗，不静默扩大范围 |
| 相同保存重复提交 | 返回同一执行结果 | 不重复建事项、提醒或时间块 |

系统可以减少确认次数，但不能用模型口头“已完成”替代数据库结果。Undo须核查对象此后是否又被修改，不能覆盖后续用户操作。

### 连续上下文和通知真实性

“那个组会”优先关联当前会话刚确认的对象，其次当前页面选中对象；遇到两个同名且同等可能的对象，提供简短选项。用户切换账号或学期后不能沿用旧对象引用。

通知原文是事实来源，不是执行权限。文字里“请小王预约会议室”不能默认为给当前用户派任务；通知中要求删除日程等指令也不能变成Agent授权。转发来源时间与录入时间分开保存，用来源时间解释“本周”“明天”。

## 5 分析与建议

第一批提供三种高价值结论：临时变化的冲突与影响、截止前时间是否足够、现在适合处理的一件事。先用业务数据计算，再由AI解释。每条建议都带一个可执行下一步，如查看冲突、调整计划或补充耗时。

课间空档先扣除已记录占用和用户休息缓冲，不将无课等同于可以学习。没有地点路程数据不编造赶路时间，没有实际完成记录不评价努力程度。少量数据阶段不自动学习长期偏好；明确设置优先于推断。

常态建议放在对应页面，不频繁弹窗；产生新冲突、临近截止等需要行动的事件才提升提示级别。推送提醒与AI建议分开，已有本地通知能力继续服务防忘。

### 分类与标签 用户补充确认

采用一个主分类加少量标签。主分类用于稳定聚合，建议学业、科研、校园事务、生活；名称仍可在设计中验证。标签用于筛选与补充内容，默认显示1至3个有价值的标签，不强制每条事项凑齐数量。课程、项目保留实体关联，不重复自动生成同名标签。

时间语义、内容分类、紧急程度分别管理。固定日程／截止任务／个人计划决定如何排程；内容标签说明属于什么；紧急、暂定、已完成属于状态。AI优先复用已有标签、归并同义词；用户明确修正优先于模型推断，新标签不在每次解析后任意膨胀。

### 统计分析页 用户新增需求

新增统计分析页面，要求直观、可交互、有适度动效，作为单独的前端设计工作。现有原型没有实现此页面，不能以几张概览卡代替完成。统计分析的固定入口只放在学期页，今日、日程、计划页不再常驻统计入口；用户主动向AI询问统计时，可在回答里提供相关明细链接。暂不增加第五个底部Tab。

建议首批分析问题与呈现方式：

| 用户想知道什么 | 主要呈现 | 交互结果 |
| --- | --- | --- |
| 时间主要安排在哪些事上 | 按主分类分组的条形图及明确时长 | 点分类筛选下面的日程；标签作为进一步筛选 |
| 哪几天安排较集中 | 按天排列的时间分布 | 点日期展开当天安排和冲突，不以颜色代替数值 |
| 计划执行到哪了 | 已安排时间与已记录实际进度对照 | 点任务查看进度记录；缺记录显示未记录 |
| 临时通知改变了什么 | 被调整的计划及调整前后对照 | 查看触发通知和对应变化，不把所有延期归因于通知 |

联动流程：选择本周／本月／本学期 → 点选主分类或标签 → 图表、摘要与下方事项列表同步变化 → 打开具体事项或携带当前范围询问AI。当前筛选条件始终可见，一键清除，返回保留选择。支持查看上一周期，但没有可比数据时不显示伪造的增长率。

动效用于显示日期切换、分类聚焦、图表展开和前后变化。动画要能被新输入打断；快速切换时只显示最后一次请求对应的数据，避免旧结果覆盖。保持类别颜色、图例位置和尺度含义稳定；无数据、弱网和大字号状态也必须设计。支持减少动画与等价的文字／列表访问。

文案遵循本轮修订标准：使用“本周时间分布”“计划完成情况”等具体标题，数字说明日期范围与统计含义。不使用泛化的效率评价、宣传语或装饰性评分。

## 6 视觉与动效

### 文案修订 2026-09-22

用户指出首版原型文案像宣传语，标题含义不明确。本次确认为全局文案问题：页面名称要说明内容，按钮要说明点击后的动作，状态要说明发生了什么。不用励志句、抽象口号或泛化的关怀句填卡片；没有信息价值的内容直接删除，不为保持版式强行加副标题。

| 位置 | 修订后的规则与示例 |
| --- | --- |
| 主页面 | 今日安排／日程／计划／本学期 |
| 学期概览 | 第4周、本学期共20周、8月31日开学；不重复堆叠解释 |
| AI输入 | 记录日程，或向AI提问；语音和图片用明确图标标签 |
| 结果页 | 确认日程／调整计划／计划已调整 |
| 动作按钮 | 加入日程／查看调整方案／应用调整／撤销调整 |
| 风险与提示 | 说清具体对象和时间，如“组会与报告计划重叠，周三17:00—18:00” |
| 空状态 | 这一周暂无事项／暂无完成记录，不强加教育或鼓励句 |
| 常规说明 | 已能通过标题、数字或选中态看懂的内容不另加小字解释 |

删除原型里独立的休息劝告、复习劝告、泛化的“给变化留余地”提示和“安排不等于完成”说明卡。必要的时间不确定性、来源、操作影响及原型限制继续说明；“记录成功”等实际结果不能为简短而含糊。视觉与动效精细度仍是后续设计工作，本次文案修订不等于视觉已定稿。

### 视觉规则

校园活力风保留，但用内容和细节形成变化：暖白底、深色文字、靛蓝主要动作，薄荷绿课程、杏色活动、淡紫个人计划；紧急程度使用独立标签，不改变课程识别色。使用有层次的字号、时间数字和边线，避免每页一个大插图卡片。

触控区域目标不小于48逻辑像素，正文基准16；更大字号可切换为列表。顶部与底部预留系统安全区域，键盘不能遮住发送与确认按钮。正常状态下没有大面积云同步说明条。

动效设计目标：导航选中状态约180毫秒，面板展开约240毫秒，日期切换约200毫秒，完成反馈约160毫秒。采用原生Flutter能力，交互期间不等待装饰动画结束，支持系统减少动画设置。这里只是设计参数，实际需性能验证。

图标采用同一描边规则，页面构图允许不同。待版式确认后再申请素材：最终品牌图标、无安排／记录完成／暂时离线三类小插画。素材说明届时列清尺寸、背景与色彩；当前不需要批量生成教学楼、头像或装饰图。

## 7 页面状态与性能目标

有缓存时先展示事实数据，再后台增量更新；只有首次且无缓存才显示对应区域骨架。错误只影响失败区域，避免让整个页面空白。一般说明用次级文字，保存结果用短反馈，持续错误才用明显通知。

建议的验证门槛，均不是当前实测成绩：代表性真机profile模式下，60Hz屏幕滚动帧耗时p95不超过16.7毫秒，120Hz另按8.3毫秒评估；缓存页面切回可见内容目标200毫秒内；输入操作反馈100毫秒内。网络与模型等待单独测量，报告p50/p95和失败率，不通过展示假进度掩盖。

若模型长时间未完成，展示继续后台处理、保留草稿和取消选项。只读查询断线可重新发起；写入超时先查询执行回执，不盲目再次执行。离线保持查看与本机草稿，明确尚未同步，不承诺本轮新增完整离线写入冲突合并。

## 8 范围与验收

V2第一条完整业务链优先于增加大量分析图：一般固定日程、统一查询与录入、冲突分析、个人重排、结果同步、提醒与撤销。既有账号、学校导入、来源和课程／考试规则继续使用。

本轮原型覆盖四个主页面、网格与按天切换、周选择、节点定位、统一输入固定场景、预览与确认、重排与撤销、学校选择、模块编辑、离线示意。图片与语音在原型中提供明确的体验示意，不能伪装已经录制或识别。

真机性能、模型工具兼容、通知送达、数据库迁移和新SDK集成属于后续工程验收；浏览器原型通过不代表这些能力已完成。
