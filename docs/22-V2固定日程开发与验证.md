# V2 第一批正式开发 固定日程

版本0.2.0，2026-09-26。此次是Flutter与后端的真实功能开发，不是继续修改HTML原型。完整Agent、多轮操作与真实统计页尚未实现。

## 已实现

- 独立固定日程：创建、修改、取消、修改历史、原始通知保留。
- 时间可精确到区间，也可保留只知道开始、日期、周次或未知的状态；不补造结束时刻。
- 四个主分类与账号范围内复用的标签；当前接入固定日程，尚未迁移全部历史任务的分类。
- 日期范围查询统一返回课程、固定活动、考试、个人计划和截止节点。跨天活动在客户端分段绘制，原始区间不变。
- 所有现有排程、重排、可学习时间检查与风险入口使用包含固定日程的快照；新增日程会使旧方案版本失效，不能自动挪动固定活动。
- 提前提醒随活动时间变更重新计算，取消活动后移除有效提醒；点击活动通知可进入对应日程详情。
- AI文字解析新增create_event类型；图片／语音转写后的解析也进入同一日程确认表单。候选确认前不会创建正式日程，确认时保留原文并防止重复添加。
- Android今日／日程页接入真实查询；手工录入、分类标签、详情、修改、取消可用。旧周请求不能覆盖新周，离线保留事实缓存，跨周和恢复前台重新查询。

## 关键文件

- `services/api/app/calendar_events.py`：真实接口与统一投影。
- `services/api/app/event_schemas.py`、`event_store.py`：时间校验、标签与提醒、共享快照。
- `services/api/alembic/versions/0010_calendar_events.py`：新增三张表，不删除现有业务数据。
- `apps/mobile/lib/features/calendar/`：日程页面、数据缓存、录入与详情。
- `scripts/verify_calendar_api.py`：使用合成通知验证真实模型，默认在隔离数据库执行；显式传入base-url才访问指定服务。
- `deploy/deploy_cloud.py`：先构建和备份，再迁移并替换本项目API／worker；失败恢复旧镜像与配置，不重置数据卷。

## 正确性与回归

固定日程新增行为先由失败测试验证旧代码不存在该能力，再实现。PostgreSQL升级、降到0009、再次升级已在独立生成的schema中完成。没有对真实云端数据库执行回退测试。

独立只读审查发现并修复：422校验失败后表单被永久冻结、手工日程编辑可能清空原通知、今日页面跨周仍读取上周。追加了对应回归。另用失败测试复现并修复了课程本地时区与活动UTC时间混排导致的排序错误。

一项原有operations测试只冻结排程时钟，未冻结操作时钟，随真实日期推进而失败；在干净基线归档中复现相同失败后，只修正测试时钟。并行Flutter全套曾出现异步等待不稳定，完整验收使用单并发运行并保留日志。

验证证据存放于本机output目录：

- `events-backend-final.log`：PostgreSQL完整回归111项通过。
- `flutter-events-final.log`：Flutter完整回归，87项通过。
- `verification/events-model.json`：真实模型3个合成例子通过：明确区间的组会、暂定周次会议、作业截止。
- `verification/events-ui/`：实际Flutter渲染的日程与表单截图，不是网页截图。

本批尚未在物理手机上验证系统通知送达或帧率，不将模拟接口的widget测试称为原生端到端测试。使用现有调试签名，不是应用商店正式签名。

## 与完整V2的边界

当前仍使用已有模型解析流程，新增固定活动支持不等于已接入完整Agent工具循环。未预置的动态类别创建、全应用标签管理、统计聚合接口和完整高保真Flutter迁移继续按19的后续阶段执行。没有引入Jev或未经验证的新框架。
