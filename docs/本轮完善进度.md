## 1.1.1 · 2026-10-17

Android 1.1.1、构建号 12，后端 1.1.1。发行包、APK、校验值在[交付说明](交付说明.md)。

这版主要是把标签从“模型随手生成”改成“程序按词表归类”：

- 标签改用共享的程序规则，通知提取和标签生成拆成两件事，标签这条路上不再调 LLM。
- 组会、座谈会、班会、例会归到会议；彩排、联排归到排练；讲座、实验作业、运动这些同用途的名字统一。
- 已有标签自动整理，去掉了自动合并提示和分类筛选按钮。标题、原文、历史 ID 映射都保留，用户不会因为整理一下就找不到旧记录。
- 点标签能看跨学期的事项和日程，已完成、已取消的也在里面，支持翻页、重试、打开详情。
- 新增记录、手动表单、助手工具、历史记录共用同一套标准标签。用户手动重命名和合并这条路仍然有，动之前会先给影响看。
- 使用、功能、接口、开发、设计、部署、参赛文档全部更新，Word 同步。
- 客户端、服务端、反馈里携带的版本号统一成 1.1.1，Android 构建号往上加。

回归、线上合成账号、模拟器升级的结果都在交付说明里。历史测试各带各的日期、版本、设备；真实学校登录、厂商电池策略、真人使用成效这几项按对应的证据说，不硬往这版上套。

## 怎么查看用户反馈

用户在“账户 → 反馈问题”提交后，内容落在服务端 `user_feedback` 表。在配好了服务器 SSH 的维护电脑上：

```powershell
python scripts/view_feedback.py
python scripts/view_feedback.py --limit 100 --category reminder --no-open
```

只读查询，默认取最近 50 条，输出到 `output/feedback/latest.html`。页面列出时间、账号、类别、描述、期望、App 版本，再跑一次才会刷新。普通用户那边没有查别人反馈的接口，这是故意的。

用户直接说给我的文字意见，另外整理在[试用与问题记录](试用与问题记录.md)。那部分和服务器上的反馈条数不是一回事，也别当成一次独立试验。
