# 第五批：现实变化与最小扰动重排

日期：2026-09-20。分支：`codex/android-foundation`。接续09的初次自动排程，本批打通“通知 → 现实变化预览 → 现实确认 → 影响分析 → 个人重排候选 → 独立确认”。

## 使用方式

“计划 → 调课 / 停课 / 现实变化”提供原始通知输入、AI建议和手工填写。文字快速记录识别为现实变化意图时也可转入此页。类型支持单次调课、单次停课、明确所选课次的放假停课、补课、固定活动。原文或手工核对依据必填，先展示原课次、新安排、受影响计划、任务余量和固定冲突。涉及固定冲突时列出安排名称及冲突时刻，另行勾选确认记录现实情况。

确认现实变化后课表立即失效并重新加载当前周，风险、计划查询使用新修订。学校新事实不会自动移动个人时间块。用户再点“分析最新安排并生成重排候选”，核对各块新旧时刻和移动统计，独立确认后才应用。也可从个人计划列表直接发起重排，处理考试详情修改、学习时间变化等造成的影响。

## 现实层与来源

新增迁移`0007_reality_changes`。原始周期课表不覆盖，变化以`RealityChange`保存原文、请求、前后课次、影响快照、基准修订号与应用回执。课次ID稳定：单次调课保持原课次身份，只替换这次起止时刻与地点；其他周的课程不跟着改变。多条已确认变化按学期修订顺序叠加。

`occurrences.py`统一展开原课表及应用变化，周课表、容量检查、初次排程和重排共用同一投影。新增补课/活动也进入固定占用。停课/放假只释放明确选中的课次，不擅自推断停课范围或把假期设成禁止学习。

创建变化预览不会应用真实安排。应用时校验账号归属、学期修订、目标仍存在且尚未开始、新时刻处于本学期未来范围；重复确认返回原回执。已开始或过去课次的历史纠错本批不支持。跨天固定安排要求按日期分条，避免当前单日课表展示误导。最近50条预览/变化记录可重新打开查看原文与对照。

通知解析使用服务端`deepseek-flash`，仅发送用户输入、参照时间和课程标题白名单；输出经字段、时间范围和原文证据检查。模糊日期、未明确时刻保持缺失，模型结果不直接写学校安排。考试改期提示用户进入已有考试详情，避免作为新活动重复占用。本批不实现图片/语音通知，也不将教务重新导入的差异自动转成变更。

## 重排目标与确认

重排纳入本学期全部已有未来个人块，最多100项任务/300块。保留块ID、时长与工作量；锁定、已开始以及默认5分钟预留范围内即将开始的块固定。新位置必须在确认的可学习时间内，避开课程/考试/活动/禁排，并满足最早开始、截止和互斥约束。未知预留考试时间、失效任务信息或覆盖超过剩余工作量时先要求核对。

采用CP-SAT分层目标：

1. 最小化被移动的任务数量；一个任务移动多个块仍计一项。
2. 在第一层已证明最优时，最小化所有开始时刻绝对偏移的总和。
3. 在前两层已证明最优时，偏向较早安排。

每轮共享10秒求解预算，保存每层状态、目标值、界和总耗时。上一层未证明最优时不固定其值继续下一层；超时保留最后可行解，并注明未证明整体目标最优。求解后使用独立区间与归属/版本/时长校验。无法完整安排时保留原计划，不静默删除块或把未完成工作当成完成；本批不提供会丢弃旧块的“部分重排”。

“最小”只针对这组已建模的全部已有未来块、当前固定时长和硬约束，不覆盖从未纳入计划的剩余工作。补排使用初次“生成计划”入口；重排不偷偷重新拆块。本批第三层没有连续学习休息/切换成本等额外偏好。

重排候选复用持久化`PlanProposal`。接受时在学期行锁内重新检查版本、时间有效期和当前约束，仅更新需要移动的块。锁定状态、事项工作量、课程与考试保持。重复接受不重复移动。撤销只处理最近已应用且未被修改/开始/锁定的相关块，并独立检查原位置在最新现实下仍合法；旧位置被调来的课程占用时明确拒绝恢复，不能连带撤销学校通知。

## 验证结果

- PostgreSQL完整回归68项通过：沿用57项，新增现实变化5项、重排求解5项、完整确认/撤销API1项。包含单次课次范围、跨账号/过期修订、放假只取消所选范围、容量与课表一致、原文证据、锁定块、最少移动任务及分钟、不可行不丢块、撤销拒绝与现实约束解除后允许恢复。既有两条测试库弃用提示保持。
- Flutter完整回归55项通过，新增3项验证固定冲突明细、两次独立确认、已知新修订禁用现实确认，以及大字体布局。静态分析无问题。
- 真实API与模型联调脚本`scripts/verify_reality_api.py`通过12项检查。使用独立合成账号：两项任务各60分钟，原课程08:00—09:00移到09:00—10:00，另一段计划锁定；实际求解仅移动1项任务，开始时间偏移120分钟，三层均返回OPTIMAL。确认现实后个人计划保持；确认重排后ID/时长保持且无冲突；撤销到已被课程占用的旧位置返回拒绝。
- 结果位于`output/verification/reality-api.json`。模型样例只证明这条明确通知的接入闭环，不代表通用解析准确率；没有使用真实学生数据、用户账号或教务会话。
- 合成UI渲染在`output/verification/changes-ui/`，已检查现实变更核对页、重排对照页及大字体页面。它们是组件渲染证据，本批未宣称已在用户模拟器安装新包。
- 只读审查发现并修复：锁定块仅与可移动块重叠时错误拒绝重排、现实确认后课表缓存清空却未重新加载，以及固定冲突确认缺少名称和时刻明细。相应回归通过。
- 最后复测补充同一应用时刻的确定性测试：最新已应用方案按单调递增的学期基准修订号排序，避免相同时间戳时用随机UUID误判撤销顺序。

Android debug构建成功，APK内已核对现实确认与个人重排入口，未混入原生通知测试入口。入口为`lib/main.dart`，目标x86_64模拟器，导出至`output/apk/SemesterOS-0.1.0-debug.apk`并附SHA-256与源码提交记录；物理手机仍需对应架构、签名与真机测试。教务读取Node回归3项通过。
