# 通知理解与助手交互重构

2026-09-30 用户已要求开始实施 findings2 与通知样本中的全部问题。版本名保持 0.1.0。既有账号、学期、课表与已保存事项保留；只使用增量迁移。真实通知原件不加入 Git，验证样本使用一致的匿名人物和测试身份。

## 已确定的体验

- 日程记录允许没有开始、结束、地点、耗时、截止等字段。只在当前操作确实依赖它时补充信息，不因缺项阻止保存或整页展示。
- 时间保留原话：无期限、等通知、预计日期、候选日期、课程节点、办理窗口与明确截止不同。办理窗口不自动占用整个窗口；不猜结束时刻、耗时、23:59 或截止延长。
- 首次身份引导包含学校、学院、专业、班级、培养层次、入学年份、自由填写的班级职务。职务可空，资料可稍后填写与修改。资料是本人自述背景，不授予权限，也不能代替临时参与条件。
- Agent 用本人资料和通知来源判断适用对象、职责、参与条件、提交步骤、后续修改。通知中的我属于消息发出者，@别人不默认成为用户任务。
- 回答用简短中文，先给必要结论；对关键日期、时刻、地点和动作使用强调。避免重复原文、工具字段、宣传语、双语解释以及预览之前无意义的再确认。
- 对话中每条消息正常展示，不整体折叠。历史与大量日程按需加载。冷启动进入新会话，后台返回保持当前会话和草稿；未发送草稿可恢复，已发送历史由用户打开。
- 编辑已发送问题后重新回答，保留原对话作为历史；已经保存的业务修改独立使用撤销，不隐式回滚。
- 对话的标题、空状态、消息、结果、确认、进度、失败、输入、附件、录音、历史与菜单统一重绘。使用真实结构化结果和信息层次体现智能，控件保持 48dp 触达与大字号支持。
- 手机保留七列周课表入口与完整日程入口，用户可切换。时间轴用实际当前时刻定位，包括事项之间的空档；隐藏和后台停止计时。
- 修复节次时间编辑确认后跳到上一个输入项，并检查选时、批量编辑、增减节次、验证和保存的状态一致性。

## 后端契约

GET /api/v1/me/profile 返回 version、school、college、major、class_name、education_level、entry_year、class_role、onboarding_completed。字符串为空表示未填写，education_level 为 undergraduate 或 postgraduate，年份可空。

PUT /api/v1/me/profile 使用上述字段与 expected_version，账号隔离与乐观版本检查。新资料传入 Agent 时标记为自述数据，不能作为系统指令。

现有 ItemTime 与事件/事项 ID 保持兼容。扩展可选 expression、办理窗口/候选日期语义与结构化 details（参与条件、材料、提交渠道、接收对象、提前到场等），只验证用户实际提交的值。旧客户端请求仍有效。时间未具体化的对象不生成虚构占用。

对话增加编辑重答与游标读取契约。编辑请求产生新的回复分支，原应用回执保留；迟到模型结果不能恢复已作废的预览。历史按页读取，记录卡片先显示相关少量结果与总量入口。

## 验收依据

通知案例至少覆盖无期限改昵称、班会先有时间后补地点、班委汇总与学生个人办理、带截止的登记、纸质办理窗口与电子截止、线上课程考试周、被点名的分工、预计/候选日期和后续修改通知。每例核对提取、身份适用、追问次数、预览耗时、保存结果、更新去重及提醒行为。

全量 API/Flutter/教务回归及增量迁移检查通过后，使用独立测试账号在实际软件界面验证通知流程。大字、小屏、横屏、键盘与录音状态截图检查全部新增界面。不得将构建和测试通过称为所有体验已验收。
