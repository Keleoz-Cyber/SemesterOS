# 自动排程候选与确认实施计划

目标：在已确认输入上用OR-Tools生成未来7/14/28天个人计划，经独立校验、预览及用户确认后落库。初版保持全部已有块的位置，只追加未覆盖工作；自动移动与最小扰动重排留给下一阶段。

- [x] 先写求解测试：固定占用、最早开始/截止、不可拆分、45/15分钟分块、尾段、容量不足、分块限制、明确部分诊断、已有覆盖不重复安排。
- [x] 服务端接入并锁定OR-Tools依赖；整数分钟可用域保守处理真实边界，限时求解并独立验证输出；不把超时或分块失败称为普遍无解。
- [x] 新增个人计划块、候选和操作历史；生成不写正式计划，接受/撤销/锁定/取消具备归属、版本、幂等与最新约束检查。
- [x] 进度、完成、取消事项和学习时间变更，预览真实受影响块并明确确认；锁定块不得被静默取消或移动。任务编辑减少工作量时必须处理已有覆盖。
- [x] 余量计算接入有效计划：只扣其他任务占用，自己的覆盖不重复扣；过期计划不等于工作完成，失效块单独标出。
- [x] Flutter提供生成范围、任务目标、拆分设置、候选明细、部分方案明确确认、计划列表、锁定/取消/最近方案撤销，并更新相关确认页。
- [x] PostgreSQL与Flutter回归、独立只读审查、合成数据真实API和可见UI验证、Android构建；更新说明并交付当前开发分支。

验证：后端57项、Flutter52项、Node3项通过；静态分析无问题，真实合成API共150分钟/11项检查通过，Android debug构建成功。详细范围与证据见[09-自动排程候选与确认验证](../../09-自动排程候选与确认验证.md)。

第一版求解请求有10秒预算，候选持久化；不实现长期作业队列、拖拽修改或自动调课应用。范围与限制直接展示，模型不参与数值求解，不修改学校课程/考试。
