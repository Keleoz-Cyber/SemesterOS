# 课程事务、考试中心与学期时间轴实施计划

目标：按03的四入口架构，聚合现有事实、任务、风险和历史，建立显式考试—复习任务关联，补齐考试改期预览确认。

执行：executing-plans；关键关联和时间行为先写测试。当前codex/android-foundation分支继续开发，保留本机devtools_options.yaml。

- [x] course/semester hub查询测试：账号隔离、课程身份分组、关联事项与实际课次/变化、同修订风险。
- [x] 考试复习测试：创建或关联任务、明确耗时与截止策略、重复防护、旧客户端编辑保持关联、取消考试时复习保持并提示。
- [x] 考试改期测试：预览只读、版本/修订校验、来源历史、提醒重算、可选同步复习截止、旧计划保持且新冲突可重排。
- [x] 时间轴测试：周次/范围/未知/越界不补造日期；可用时间与有效计划统一计算，高负载与截止集中分开表达。
- [x] 服务端centers.py、exam_planning.py及schemas；复用现有JSON payload、ItemRevision和幂等记录，不复制日程。
- [x] Flutter课程/考试/时间轴页面接入课表和学期Tab；课程默认关联新增事项，考试设置复习与改期入口，点击节点打开真实事项。
- [x] PostgreSQL/Flutter/Node回归、合成真实API闭环、UI渲染与审查、APK构建、文档、提交推送。

规则：只有相同学校source_id才自动归组多条授课模式；无该标识不按同名猜测关联。复习任务是独立可规划工作，考试改期同步其截止必须显式确认，移动个人块仍走独立重排。周负荷展示可用分钟、有效计划覆盖与截止集中；不以单周剩余容量冒充跨周可行性判定。
