# 部署与维护

本页说明如何从源码启动拾日、配置模型服务、生成Android安装包，以及备份和清理运行环境。命令以Windows PowerShell为主，均从仓库根目录执行。

## 1. 准备环境

需要Python 3.12、Docker Desktop、Flutter、Android SDK和JDK 21。Flutter的Dart版本要满足`apps/mobile/pubspec.yaml`中的`^3.12.2`。教务页面的JavaScript测试还需要Node.js。

后端依赖以`services/api/requirements.lock`为准。开发脚本会创建`services/api/.venv`并安装依赖，所以首次启动可能较慢。Android脚本会查找JDK 21；找不到时可通过`SEMESTEROS_JDK_HOME`指定目录。

将`.env.example`复制为`.env`，填写以下内容。已有配置时编辑原文件即可。

| 配置项 | 用途 |
| --- | --- |
| `POSTGRES_PASSWORD` | 本地PostgreSQL密码 |
| `DATABASE_URL` | 后端连接数据库的地址，密码应与上项一致 |
| `DEEPSEEK_API_KEY` | 文字助手调用模型所需的密钥 |
| `DEEPSEEK_MODEL` | 默认`deepseek-flash` |
| `DEEPSEEK_BASE_URL` | 默认`https://api.deepseek.com` |
| `MEDIA_WORKER_MODE` | 默认`managed`，后端启动时同时启动后台处理进程 |

密钥保存在运行环境中，不写入App、不上传到Git。没有配置模型时，手工记录和日程查看仍可使用，助手会提示暂时不可用。

## 2. 启动本地服务

先打开Docker Desktop，再执行：

```powershell
.\scripts\dev.ps1 -Action Api
```

脚本会启动PostgreSQL、安装Python依赖、执行数据库升级，再在8871端口启动后端。数据库只映射到电脑的`127.0.0.1:55439`。

可以在另一个窗口检查服务：

```powershell
Invoke-RestMethod http://127.0.0.1:8871/health
```

正常返回包含`status: ok`、版本号和数据库类型。该检查只能说明服务和数据库能连接，不能证明模型或图片、语音识别都正常。

启动App：

```powershell
.\scripts\dev.ps1 -Action Android
```

模拟器里的开发版默认使用`http://10.0.2.2:8871`。手机不能用这个地址，手机连接方法见[移动端开发说明](../apps/mobile/README.md)。

## 3. 使用容器运行完整后端

想让API也在Docker中运行，可以执行：

```powershell
docker compose --env-file .env -f deploy/compose.yaml up -d --build
```

配置包含数据库、一次性的数据库升级任务和API。数据库通过健康检查后才执行升级，升级成功后才启动API。API仍通过本机8871端口访问。

API默认会启动后台进程。这个进程既处理图片和语音，也处理助手请求；不要因为名字叫`media_worker`就认为它只负责媒体识别。本机运行时，把`.env`里的`MEDIA_WORKER_MODE`设成`external`，就需要自己单独启动同配置的worker，否则请求可能一直等待处理。本地Compose没有传入这个变量，仅修改`.env`不会改变容器模式；容器需要在Compose的`environment`中显式配置。

服务器部署使用[compose.cloud.yaml](../deploy/compose.cloud.yaml)。它将API和worker拆开运行，共用数据库、上传文件和识别模型；API只监听宿主机回环端口，应在前面配置HTTPS反向代理。`APP_TAG`用于选择镜像版本，`MODEL_ROOT`用于指定模型目录。该配置适合单台服务器，不包含完整的多机运维方案。

## 4. 准备识别模型

文字助手调用在线模型；图片OCR和语音识别在后端机器上运行。语音模型的准备命令是：

```powershell
.\services\api\.venv\Scripts\python.exe .\scripts\setup_media_models.py
```

脚本下载固定版本的SenseVoice模型并校验文件哈希，下载位置固定为`.local-data/models`。`SENSEVOICE_MODEL_DIR`改变的是后端读取模型的位置，不会改变下载位置。使用自定义路径时，需要将下载好的模型复制或挂载到该位置；容器也需要挂载模型目录。

图片识别使用RapidOCR。服务器还需要对应模型文件和可写的上传目录；云端配置中的`RAPIDOCR_MODEL_DIR`指向`/models/rapidocr`。上线前分别上传一张测试图片和一段测试录音，确认任务完成且识别文字正确；只确认文件上传成功还不够。

## 5. 生成Android发行包

先在`apps/mobile/pubspec.yaml`和`services/api/app/version.py`中保持版本一致。准备原来的签名文件，继续使用同一证书才能覆盖安装已有App。

```powershell
python .\scripts\build_release.py --build
```

脚本会构建、对齐、签名并检查APK，成功后将安装包写入`output/apk`，将包大小、SHA-256、证书和构建信息写入`output/release`。目前脚本内的正式API地址是`https://semesteros.keleoz.com`。

该脚本的Gradle步骤使用离线模式。新机器应先完成一次普通Android构建，让所需依赖下载到缓存中。默认签名位置是当前用户的`.android/debug.keystore`；使用其他签名时传入`--keystore`、`--key-alias`和对应的`--expected-cert`，密码通过`SEMESTEROS_KEYSTORE_PASSWORD`提供。

脚本检查64位库的16KB对齐，这不等于已经在16KB页面大小的真机上运行过。安装和实际操作仍是单独的验收步骤。

## 6. 备份和恢复

需要一起保存数据库和上传文件。数据库记录里有图片、录音的文件位置，只备份其中一项会造成记录与文件不匹配。密钥和模型配置也要另行保管，模型文件可按固定版本重新准备。

本地Compose数据库可以这样导出。命令先让容器生成备份文件，再复制到电脑，避免PowerShell重定向破坏二进制文件：

```powershell
New-Item -ItemType Directory -Path .\tmp\backup -Force
$dbContainer = docker compose --env-file .env -f deploy/compose.yaml ps -q db
docker exec $dbContainer pg_dump -U semesteros -d semesteros -Fc -f /tmp/semesteros.dump
docker cp "${dbContainer}:/tmp/semesteros.dump" .\tmp\backup\semesteros.dump
```

`tmp`会被项目清理脚本删除。导出完成后应将备份移到项目外的固定备份位置，并另外保存Compose中的媒体卷。恢复时先在新的测试数据库中使用`pg_restore`导入，核对学期、课程、任务数量及上传文件能否打开，再按维护计划切换正式服务。

## 7. 常见问题

**助手一直等待。** 先检查worker是否运行，再看模型密钥、网络和worker日志。服务健康接口正常不能排除worker问题。

**模型不可用。** 检查`DEEPSEEK_API_KEY`和模型地址。输入内容通常仍保留，可以稍后重发，也可以手工记录。

**模拟器能用，手机不能连接。** 先检查API地址。`10.0.2.2`是Android模拟器访问电脑的特殊地址，不能原样用于手机。

**数据库升级失败。** 查看升级任务的错误，修复后重新执行`alembic upgrade head`。不要用删除数据库来掩盖升级失败。

**图片或录音一直没有结果。** 检查worker、模型路径、文件权限和识别错误码；上传完成与识别完成是两个步骤。

## 8. 清理开发文件

先预览要删除的内容：

```powershell
.\scripts\clean.ps1
```

确认列表后执行：

```powershell
.\scripts\clean.ps1 -Apply
```

需要连Python环境和本地识别模型一起清理时，再加`-DeveloperCaches`。清理前停止占用文件的开发服务。脚本保留源码、Git、密钥、`.env`、原始本地媒体，以及`output/apk`和`output/release`；会删除其他输出、构建缓存和`tmp`内容。清理后再次开发需要重新安装相应依赖。
