# 部署与维护

这一页讲怎么从源码把拾日跑起来、怎么配模型、怎么打包、怎么备份。命令以 Windows PowerShell 为主，都在仓库根目录执行。

## 1. 环境

需要 Python 3.12、Docker Desktop、Flutter、Android SDK、JDK 21。Flutter 自带的 Dart 得满足 `apps/mobile/pubspec.yaml` 里写的 `^3.12.2`。另外教务页面的 JavaScript 测试要 Node.js，不跑那部分测试可以不装。

后端依赖以 `services/api/requirements.lock` 为准，别看 `requirements.txt`，那个只写了主干。开发脚本会自动建 `services/api/.venv` 并装依赖，所以第一次启动要等一会儿。Android 脚本自己去找 JDK 21，找不到就用 `SEMESTEROS_JDK_HOME` 指个目录给它。

把 `.env.example` 复制成 `.env`，然后填这几项：

| 配置项 | 用途 |
| --- | --- |
| `POSTGRES_PASSWORD` | 本地 PostgreSQL 的密码 |
| `DATABASE_URL` | 后端连库的地址，密码要跟上面一致 |
| `DEEPSEEK_API_KEY` | 文字助手调模型用的密钥 |
| `DEEPSEEK_MODEL` | 默认 `deepseek-flash` |
| `DEEPSEEK_BASE_URL` | 默认 `https://api.deepseek.com` |
| `MEDIA_WORKER_MODE` | 默认 `managed`，后端起来时顺带把后台处理进程也拉起来 |

密钥只待在运行环境里，不进 App，也不进 Git。没配模型的情况下，手工记录、看日程照样能用，只有助手会提示暂时不可用——这个降级是故意的，别把助手挂了当成整个 App 挂了。

## 2. 本地跑起来

先把 Docker Desktop 打开，然后：

```powershell
.\scripts\dev.ps1 -Action Api
```

这条会启动 PostgreSQL、装 Python 依赖、跑数据库升级，最后在 8871 端口起后端。数据库只映射到本机的 `127.0.0.1:55439`，不对外。

另开一个窗口验一下：

```powershell
Invoke-RestMethod http://127.0.0.1:8871/health
```

返回里该有 `status: ok`、版本号和数据库类型。请注意这只证明服务和库能连上，模型、图片识别、语音识别是否正常它一个都不管。

再启动 App：

```powershell
.\scripts\dev.ps1 -Action Android
```

模拟器里的开发版默认连 `http://10.0.2.2:8871`。手机用不了这个地址，手机怎么连写在[移动端开发说明](../apps/mobile/README.md)里。

## 3. 用容器跑完整后端

想让 API 也在 Docker 里，用这条：

```powershell
docker compose --env-file .env -f deploy/compose.yaml up -d --build
```

里面有三样：数据库、一次性的数据库升级任务、API。数据库过了健康检查才跑升级，升级成功才起 API。API 还是走本机 8871。

这里有个坑。API 默认会拉起后台进程，这个进程不光做图片和语音，助手的请求也归它处理——名字叫 `media_worker`，但别以为它只管媒体。本机跑的时候，如果把 `.env` 里的 `MEDIA_WORKER_MODE` 改成 `external`，那就得自己再起一个同配置的 worker，不然请求会一直挂着等。另外本地的 Compose 没有把 `MEDIA_WORKER_MODE` 传进容器，改 `.env` 对容器里的模式没影响；要在容器里换模式，得写进 Compose 的 `environment`。

服务器那边用 [compose.cloud.yaml](../deploy/compose.cloud.yaml)。它把 API 和 worker 拆开跑，共用数据库、上传文件和识别模型。API 只监听宿主机回环地址，前面得挂个 HTTPS 反向代理。`APP_TAG` 选镜像版本，`MODEL_ROOT` 指模型目录。这套是给单台服务器用的，不是完整的多机方案。

## 4. 识别模型

文字助手是在线调的；图片 OCR 和语音识别都在后端机器上本地跑。语音模型这样准备：

```powershell
.\services\api\.venv\Scripts\python.exe .\scripts\setup_media_models.py
```

脚本下载固定版本的 SenseVoice 并校验哈希，位置固定是 `.local-data/models`。`SENSEVOICE_MODEL_DIR` 改的是后端去哪儿读，不改下载地儿。你要用自定义路径，就得把下好的模型复制或者挂载过去，容器也一样得挂。

图片走 RapidOCR。服务器上得有对应的模型文件和可写的上传目录，云端配置里的 `RAPIDOCR_MODEL_DIR` 指向 `/models/rapidocr`。上线前记得真传一张图、真录一段音，看任务跑完、识别出的字对不对。光看文件上传成功不算数。

## 5. 打 Android 包

先把版本对齐：`apps/mobile/pubspec.yaml` 和 `services/api/app/version.py` 两处要一致，当前构建号是 12。签名文件用原来那份，证书换了就覆盖不了已装的 App。

```powershell
python .\scripts\build_release.py --build
```

脚本会构建、对齐、签名、检查 APK，成功后把安装包放进 `output/apk`，把包大小、SHA-256、证书、构建信息放进 `output/release`。脚本里写死的正式 API 地址是 `https://semesteros.keleoz.com`。

它的 Gradle 步骤是离线模式跑的。新机器第一次得先做一次普通 Android 构建，把依赖下到缓存里，不然会失败。默认签名位置是当前用户的 `.android/debug.keystore`；换别的签名要传 `--keystore`、`--key-alias` 和 `--expected-cert`，密码给 `SEMESTEROS_KEYSTORE_PASSWORD`。

脚本会检查 64 位库的 16KB 对齐。检查通过不等于在 16KB 页面大小的真机上跑过，装上去点一遍还是得单独做。

## 6. 备份和恢复

数据库和上传文件必须一起存。库里的记录记着图片、录音在磁盘上的位置，只备一半，恢复出来就是一堆指向空气的路径。密钥和模型配置另外保管，模型文件按固定版本能重新准备。

本地 Compose 的库这样导。先让容器自己生成备份文件，再拷出来——直接把 `pg_dump` 的输出重定向到文件会让 PowerShell 把二进制搞坏：

```powershell
New-Item -ItemType Directory -Path .\tmp\backup -Force
$dbContainer = docker compose --env-file .env -f deploy/compose.yaml ps -q db
docker exec $dbContainer pg_dump -U semesteros -d semesteros -Fc -f /tmp/semesteros.dump
docker cp "${dbContainer}:/tmp/semesteros.dump" .\tmp\backup\semesteros.dump
```

`tmp` 是会被清理脚本删掉的目录。导完就把备份挪到项目外面的固定位置，Compose 里的媒体卷也一起存。恢复时先拿 `pg_restore` 导进一个全新的测试库，数一数学期、课程、任务，再打开几个上传文件看能不能读，都对了才按维护计划切正式服务。

## 7. 遇到问题先看这几条

**助手一直转圈。** 先看 worker 在不在，再看密钥、网络和 worker 日志。健康检查正常排除不了 worker 的毛病。

**模型不可用。** 查 `DEEPSEEK_API_KEY` 和模型地址。输入内容一般还在，稍后重发或者手工记都行。

**模拟器能用，手机连不上。** 先看 API 地址。`10.0.2.2` 是模拟器专用的，手机照抄必然连不上。

**数据库升级失败。** 去看升级任务的报错，修好再执行 `alembic upgrade head`。别删库来掩盖升级失败，那等于把问题藏起来。

**图片或录音一直没结果。** 查 worker、模型路径、文件权限和识别错误码。上传完成和识别完成是两步，别混。

## 8. 清理开发文件

先看要删什么：

```powershell
.\scripts\clean.ps1
```

确认清单再执行：

```powershell
.\scripts\clean.ps1 -Apply
```

要把 Python 环境和本地模型一起清掉，加 `-DeveloperCaches`。清之前先停掉占着文件的开发服务。脚本会留源码、Git、密钥、`.env`、原始本地媒体，以及 `output/apk` 和 `output/release`；其余输出、构建缓存、`tmp` 内容都删。清完再开发，得重新装依赖。

## 9. 版本与发布

现在 App 是 1.1.1+12，后端 1.1.1，数据库迁移头是 `0018_personal_data`。

升级过的版本里有两个值得单独提：`0017_auth_and_import` 加的是短时刷新重试和学校节次预览需要的列，只加列和索引，不动已有数据；部署时先跑升级，再更新 API 和 worker，两边用同一个镜像版本。`0018_personal_data` 是数据导出、注销和反馈那批。

标签规则的 JSON 在后端应用目录里，Dockerfile 的 `COPY services/api/app ./app` 会把它带进镜像，不用单独挂。改完规则先跑生成脚本把 Dart 那份副本同步过去，再跑两端测试。旧标签是用户进标签页时自动整理的，保存源标题和通知文字，所以上线不需要重建业务数据库。

服务器按版本建独立的 release 目录，构建镜像之后执行：

```powershell
python deploy\deploy_cloud.py --release <目录> --tag <镜像标签>
```

这个脚本会先备份数据库、媒体和配置，跑迁移，更新 API 和 worker，健康检查过了才切 `current`；中途失败就退回旧镜像和旧配置。版本升级不删真实账号，也不重建数据卷。

发 GitHub 的顺序是这样的：跑回归和打包，确认 APK 和校验值，把文档代码提交到 main，给那个提交打 `v1.1.1` 标签，然后把 APK、`SHA256SUMS.txt`、`manifest.json` 传到发行附件里。发完核对标签指向的提交、附件大小和哈希、线上健康接口报的版本，最后在旧版本上装一次新包看能不能覆盖升级。

## 10. 反馈和演示视频

看反馈：

```powershell
python scripts/view_feedback.py
```

它默认走维护电脑上已有的 SSH 配置，只读地取，输出到 `output/feedback/latest.html`。`--limit`、`--category`、`--no-open` 能调。反馈只给有权限的维护者看，那个输出文件不要提交到公开仓库。

演示视频在项目上级的 `promo/out/拾日-参赛演示-完整版.mp4`。2026-10-17 读到的信息是 4 分 52 秒、1920×1080、60fps、H.264/AAC，54,386,609 字节。它是既有视频，App 升级不会自动重录；要补拍，画面里的版本号和脚本都得重新对一遍。
