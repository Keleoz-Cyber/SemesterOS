# 部署与维护

正式 API 为 `https://semesteros.keleoz.com`，健康检查 `/health`。本地私人数据不自动迁移云端；Android 构建默认使用正式 HTTPS。本次发行状态统一见[交付说明](交付说明.md)，本手册不重复保存历史 APK 哈希。

## Windows 本地运行

仓库根目录使用 PowerShell。API 流程需要 Docker Desktop 已运行；脚本创建独立本地 PostgreSQL、Python venv、安装锁定依赖并执行 Alembic，不读取生产库作为测试库。

```powershell
.\scripts\dev.ps1 -Action Api
```

首次媒体识别另准备官方模型：

```powershell
& .\services\api\.venv\Scripts\python.exe .\scripts\setup_media_models.py
```

Android 调试运行：

```powershell
.\scripts\dev.ps1 -Action Android
```

[android-device.ps1](../scripts/android-device.ps1)选择本机 JDK 21 与设备，`SEMESTEROS_JDK_HOME` 可显式指定兼容 JDK；只影响当前进程，不改全局配置。原生插件变更后完整重启 App。[.env.example](../.env.example)仅是无秘密配置样例；真实数据库/签名/模型密钥留在私有环境，不写文档、Git、APK或发布日志。

## 云端布局与查看

服务器项目位于 `/opt/semesteros`，`current` 指向 `releases/`，根 `.env` 权限600，模型以只读目录挂载。独立 `semesteros-cloud` Compose 项目保留 PostgreSQL 与私有媒体卷；API 回环8871，数据库不映射公网，API/worker以非root用户运行。当前发布目录与迁移以交付回执为准。

服务器 Bash：

```bash
ssh keleoz-tencent
cd /opt/semesteros/current
sudo docker compose --env-file /opt/semesteros/.env -f deploy/compose.cloud.yaml ps
sudo docker compose --env-file /opt/semesteros/.env -f deploy/compose.cloud.yaml logs --tail=100 api worker
```

Nginx 独立子域站点使用[模板](../deploy/nginx-semesteros-subdomain.conf)，旧 `/semesteros` 路径为410，避免API落入博客；HTTP除ACME外转HTTPS。响应私有/no-store，私有配置/媒体不作为公开目录。网络故障分别说明连接/超时/DNS/TLS，保留缓存；不关闭证书验证或用猜测IP兜底。

## 发布与回退

先完成代码检查和版本冻结，将已核对源码放入新的 `releases/` 目录，使用唯一镜像标签。发布工具见[deploy_cloud.py](../deploy/deploy_cloud.py)，运行示例中的 `reviewed-release` 替换为本次真实目录/标签：

```bash
release_name=reviewed-release
sudo python3 "/opt/semesteros/releases/$release_name/deploy/deploy_cloud.py" \
  --release "/opt/semesteros/releases/$release_name" --tag "$release_name"
```

工具按构建 → 数据库/媒体/配置一致性备份 → 增量迁移 → API/worker启动与本机健康 → current切换执行。失败恢复旧配置/镜像；迁移新表不自动退回，应用回退须核对数据库兼容。保留发布回执并另验公网健康、未登录鉴权、实际业务和现有数据。不要用 `down -v`、清库或清媒体模拟回滚。

已持久化事实只用增量迁移，不能因UI改版重置。API与worker须使用同一发布，检查实际模块/镜像而非只看目录名。旧客户端对新增固定安排不能静默漏看后继续排程，单回退APK不能视为完整后端回退。

子域工具[migrate_subdomain.py](../deploy/migrate_subdomain.py)的 prepare-http、enable-https、retire-old 分阶段校验；已有HTTPS不能重新运行准备阶段降级。首次证书准备HTTP/ACME后：

```bash
sudo certbot certonly --webroot -w /var/www/semesteros-acme \
  -d semesteros.keleoz.com --cert-name semesteros.keleoz.com \
  --non-interactive --deploy-hook 'systemctl reload nginx'
```

恢复旧路径只从明确核对的 Nginx 配置恢复，`nginx -t` 通过后 reload；不要求恢复数据库或关闭新子域。证书续期与部署后验证分别核对。

## 业务数据备份与恢复

维护工具在 `/opt/semesteros/maintenance/`，源码为[backup_cloud.sh](../deploy/backup_cloud.sh)、[backup_integrity.py](../deploy/backup_integrity.py)、[restore_drill_cloud.sh](../deploy/restore_drill_cloud.sh)和[restore_application_smoke.py](../deploy/restore_application_smoke.py)。它们保护真实业务数据；仓库文档和构建中间文件用Git追溯，不另造备份/归档。

```bash
sudo /opt/semesteros/maintenance/backup_cloud.sh
sudo systemctl status semesteros-backup.timer semesteros-backup.service
sudo systemctl list-timers --all semesteros-backup.timer
sudo journalctl -u semesteros-backup.service -n 80 --no-pager
```

备份以文件锁防并发，短暂暂停本项目原运行的 API/worker，并在退出恢复原运行状态。数据库 dump、媒体 tar、私有配置、release引用和 manifest先写临时目录，完整性通过才形成有效备份。manifest记录哈希、表结构/内容、序列和媒体摘要；私有目录700、077掩码，不能上传GitHub。配置 timer 为北京时间03:30、Persistent补跑；手动service成功不等于定时触发已验证。

隔离演练先校验新格式备份，在无端口映射、`network=none`、独立PostgreSQL/媒体卷中恢复，核对数据库/序列/媒体/权限/配置，再用备份记录的不可变API镜像运行注册、登录、学期与任务读写。生产卷不挂载、不启动worker，退出清本次演练资源。

```bash
backup_dir=/opt/semesteros/backups/verified-backup
sudo /opt/semesteros/maintenance/restore_drill_cloud.sh "$backup_dir"
```

替换目录为已核对真实备份。无manifest的旧备份不能假定通过新演练；同机恢复不能代表跨服务器灾备或媒体模型推理成功。

## Android 发行包

本次发行 **1.0.0+8**，唯一交付路径 `output/apk/拾日-1.0.0.apk`。版本在 pubspec.yaml、Android和后端按实际发行同步；保留原包名/签名才能覆盖安装保留本机数据。此次继续沿用原测试证书以兼容覆盖安装，不作为应用商店签名；16KB设备运行尚未实测。

在仓库根 PowerShell 完成[发行验证](测试与比赛说明.md)后构建和签名：

```powershell
python scripts/build_release.py --build
```

脚本使用已有签名证书，构建正常包、核对版本/包名/Release状态、证书v2/v3、正式URL、通知图标、学校读取、三ABI、ZIP16KB及64位ELF静态对齐，直接写入唯一交付路径及 `output/release/manifest.json`、`SHA256SUMS.txt`。自有证书可用 `--keystore`、`--key-alias`、`--expected-cert` 指定；密码只从 `SEMESTEROS_KEYSTORE_PASSWORD` 读取，不写进命令或Git。覆盖安装后拉回base.apk比对哈希；卸载会清本机账号/缓存。QA/Profile包不能交付成正常用户包。

最终小manifest与一份验收日志放 `output/release/`，记录提交、版本、APK哈希、签名/ABI、测试/跳过、服务与安装结果；不留构建缓存、截图图册、旧APK或恢复ZIP。
