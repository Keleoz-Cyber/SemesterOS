# 第一批开发与验证记录

记录日期：2026-09-20。分支：`codex/android-foundation`。本批为0.1.0课表导入测试版，不是比赛完整版本。

## 1. 已实现

- Flutter Android工程与四个导航入口；实际可用页面包括注册/登录/恢复、学期创建、今日课程、周课表/列表、手工录课、导入预览和学校WebView。
- FastAPI、PostgreSQL、Alembic迁移，用户归属校验、会话刷新/撤销、一次性恢复码。
- 日历起始日与节次确认；按周次/单双周/不连续节次展开课程。
- 新增课表先预览再确认，精确重复不重复建课次；旧修订号、跨账号访问和待核对教务变化被阻止。
- 教务页面中按用户动作执行课表读取脚本，只返回字段白名单；空列表或无法确认的格式不会静默算成功。
- 本机SQLite课表缓存与系统安全存储的账号凭证；切换账号时隔离和清理，迟到请求不能写入新账号。
- 模拟器运行脚本与锁定依赖；计划、AI解析、提醒等后续能力没有冒充已实现。

## 4. 模拟器实际操作

使用独立QA测试账号与手工构造课程，无学生真实课表：

1. 在App中注册，显示恢复码，进入首页。
2. 输入第一周周一、核对示例节次，创建学期。
3. 手工输入QA_Probability、地点A305、周次1—20、周一第1—2节。
4. 预览明确显示来源、周次、节次和新增条目，确认保存后周课表出现08:00—09:50课程。
5. 停止API、强制结束App并重启，仍能看到同一缓存课程及离线提示；随后恢复API。
6. App内学校原始登录页能正常加载，显示正方系统；未登录时点击读取被明确拦截。

截图在本机`output/verification/`，不作为真实学生试用数据，也不直接用于匿名比赛材料。登录页截图只证明页面可访问，不能证明账号认证或课表读取已经成功。

## 5. 独立审查与修复

完成针对账号、缓存和导入事务的独立只读审查，已修复：

- 用会话代次拒绝旧账号的迟到响应和刷新结果；串行写入凭证，防止退出后恢复旧账号。
- 网络/限流/服务端刷新失败保留缓存；只有明确凭证失效才退出。
- 教务周次/时间模式变化标为待核对，不能伪装普通新增；手工明确添加另一课次仍允许。
- 确认导入立即根据新修订号使旧周缓存失效。
- 稳定的撤销凭证可在访问/刷新令牌轮换之后撤销原会话；不能靠退出时再次刷新登录。
- 离线启动先显示已有缓存，避免等待网络超时后才展示。

## 8. 真实页面字段提取修复

学校页面把`Array.prototype.filter`改成了索引在前的回调，与标准JavaScript不一致。原脚本按标准回调写白名单过滤，导致每条课程被提取为空对象；课程名称和星期在接口响应中实际存在。修复为索引循环逐字段复制，并拒绝非课程对象或非标量字段。

新增3项Node回归全部通过，包括在模拟的旧版filter环境下保留课程字段、剔除非白名单字段及明确报告异常记录。修正后的脚本在当前本人登录页面做了只读验证：17条记录、17条必需字段齐全、仅含白名单字段。真实内容未写入测试夹具或日志，临时WebView诊断已关闭；这不等于已完成用户确认或保存。
