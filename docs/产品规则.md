# 拾日产品规则

更新：2026-10-09。本文合并原产品需求、体验反馈、V2 方案和后续修订，记录当前业务规则；验证结果统一放在[交付说明](交付说明.md)。

## 定位与范围

把教务课程、临时通知、考试和个人任务放进同一套学期安排，通过文字、语音或图片降低整理成本，并根据已记录的事实查询空档、分析风险和调整个人计划。

主线是“通知进入 → 理解并关联 → 核对 → 统一展示 → 分析影响 → 生成可执行调整 → 确认与记录进度”。Android 是本次交付平台，支持多用户；iOS、深色逐页验收、低端真机性能仍属于后续范围。课程资料库、自动读取微信/QQ 私聊、成绩或心理判断不属于当前产品。

## 页面与日常操作

| 页面 | 主要内容与操作 |
| --- | --- |
| 今日 | 今日课程、活动与待办，正在进行/下一项，近期考试与空档建议；今日信息先于明天预览 |
| 日程 | 七列周课表、按日/列表浏览，共享日期与周次；具体课次详情显示完整名称、真实钟点和已有地点 |
| 任务 | 待完成/已完成/已取消任务、剩余工作量与学习安排；直接手工新建，学习时段设置集中在标题行 |
| 学期 | 当前周进度、考试和截止节点、现实变化、统计及学期/课程管理 |
| 统一助手 | 查询、录入、修改、规划、媒体整理和历史；携带可移除的浏览范围，不增设第五个主页面 |

手工表单继续可用，不要求用户先学会 Agent。首页模块的显隐、排序和视图偏好只改变显示，不改日程事实。紧急事项保持可见；小屏或大字号允许滚动，不能靠压小字体和操作区域塞满首屏。

文案说清对象、日期、动作和实际状态。普通查询简短回答，列表与差异交给结果卡；不重复整份通知，不用宣传语、泛化评价、假百分比或内部字段充当解释。

## 通知、身份与连续对话

- 用户资料可稍后填写或清除。学校、学院、专业、班级、培养层次、入学年份、班级职务是本人自述背景，不授予权限。培养层次仅本科/研究生，空值不默认选本科。
- 通知中的“我”属于发送者；指派给他人的任务、@他人和班委职责不自动成为本人的待办。参与条件、材料、提交方式、接收对象、提前到场与后续修改分别保留。
- 来源原话提供事实候选，不能授权删除、改课或越权操作。先查询真实对象，唯一匹配时直接准备预览；同名且无法区分时只问必要问题。
- 原消息时间、录入时间、当前真实时间和浏览范围分别处理。浏览下周不改变“明天”的解释；旧通知按已确认的来源时间解释相对日期。
- 冷启动进入新对话；后台返回保留当前对话和草稿。编辑已发送问题产生新的回复分支，原业务回执保留，不隐式撤销已保存日程。
- 删除对话不可恢复，没有回收站或撤销删除。删除停止待处理/待确认操作；迟到文字、识别和跨页面缓存不得复活它。已保存事项、回执、媒体及独立后续对话保留。

## 时间事实、冲突与出勤

| 信息 | 保存与占用规则 |
| --- | --- |
| 仅日期/周次/范围/时间未定 | 保留原精度，允许记录；不补午夜、23:59、地点、耗时或结束时间 |
| 明确开始、结束未知 | 开始点是已知事实；不推出当天后续课程均冲突，不改成一分钟活动 |
| 提前到场及正式开始 | 分开记录；已知到场区间和开始点可以证明实际冲突 |
| 完整起止区间 | 使用半开区间；前项结束等于后项开始不算重叠 |
| 明确全天 | `meaning=all_day`，保留 date/range 精度，`at/end_at` 为空；占用明确日期，不造相对提醒锚点 |
| 普通日期或否定全天 | 不转成全天占用 |
| 办理窗口/候选日期 | 是可办理范围或候选，不能自动封锁整个窗口 |
| 考试/活动仅作参考、不参加或不预留 | 确定性与是否占用分开，不占本人规划时间 |

实际冲突只列对应课次。保存固定安排前可调整/补充时间、明确保留真实重叠，或勾选本人明确已请假的课次；未处理实际重叠不能默认获得授权。结束未知等信息单独提示，不能要求处理后面的课才能保存。空闲查询和学习排程避开已知事实，后续不确定时间可作为需核对候选，不能说结束已知。

课程仍是自动安排个人任务的固定约束。用户明确陈述停课、放假或更正本人课表时，先查询范围并生成预览，不反复要求学校证明；这些操作只改变个人记录，不写回教务系统。仅询问是否停课、仅记录开会或外出，不自动改课程。

- `plan_leave`（准备请假/申请中）继续占用时间；不能当成已获准。
- `leave`（已请假）仅作用于明确课次，取消本次个人占用和上课提醒。日程、周表、今日、下一项、明天预览和周统计隐藏该课次；API/缓存/原始课次保留，课程管理和详情可恢复正常上课。
- 活动与选中的实际请假课次可一次原子保存、一起撤销；不变成停课或整学期免听。免听是独立课程状态，不按已请假展示规则处理。

## 确认、执行与撤销

查询、空档分析和候选生成不写业务数据。新增、固定安排变更、完成/取消及个人计划应用，以真实预览、版本检查和可见确认保存；模型说“已完成”不能替代数据库回执。批量按所选组核对，不夹带未选动作。

通知记录和个人重排是两个结果：确认现实变化后，即使取消重排或影响分析失败，变化仍保留；重排需另外确认。用户明确同时更正剩余量并安排时间时，可用联合预览一次保存，失败整体回滚。

保存超时先读回执或用原幂等键重试，不另建重复事项。查询、补充或澄清保留现有待确认预览；新预览准备好才替换，处理中旧预览不能并发确认。撤销检查后续修改、锁定/已开始计划及最新固定安排，不覆盖后来操作。

## 任务、建议与统计

任务缺耗时可先记录；精确余量和自动安排需要明确剩余工作量与必要时间边界。已安排、时段过去和实际完成不同；完成量与实际用时由用户记录，取消计划不减少剩余工作。

普通空闲查询按指定日程范围查找，默认每日 08:00—22:00；明确查询学习时段才用学习偏好。首页“空档与待办”只在已保存学习时段中推荐，扣除已排覆盖，尊重最早开始、等待条件和办理窗口；点击后重新计算、预览，确认才保存。

主分类与少量标签用于筛选；时间类型、分类、紧急程度和生命周期不混为一谈。用户修正优先于 AI 分类。统计区分固定占用、计划时间、实际进度和事项数量；重叠占用按并集，不把课程计划时段算成实际出席，不输出无来源的效率评分。

## 视觉与状态

数值以[晴日 v2 tokens](../design-system/shiri-v2/tokens/tokens.json)为准，完整视觉/动效规则见[MASTER](../design-system/shiri/MASTER.md)。当前主页面直接切换，导航保留选中反馈；助手单一平滑上拉；周课表整页横向切周，快速反向以最终停稳周为准。

任务仅在服务端成功后打勾、划线和收起，撤销按真实结果恢复。胶囊麦克风固定在右侧 48dp，左侧内容随收缩淡出；隐藏内容不接收触摸、焦点或读屏操作。页头、太阳/月亮轨迹使用真实时刻/周进度，刷新不重播装饰入场。

后台、隐藏、被弹层覆盖和减少动画时停计时或显示终态；减少动画解除后不补播。有缓存先展示事实，后台刷新保留布局和浏览位置；错误就地重试，失败不表示没有安排。密集周网格不能全部视作 48dp，列表、单日与详情提供更大的等价入口。当前浅色实现范围与原生验证见[交付说明](交付说明.md)；设计图不作为性能或实现证明。

## 后续范围

iOS、深色逐页验证、多端/日历同步、团队协作、桌面组件、个性化耗时学习和长期模型需独立评估。个性化至少需要用户确认的完成/耗时记录；少量数据不推断永久习惯。“长按空白格添加”仍是建议，当前沿用已有新建入口。
