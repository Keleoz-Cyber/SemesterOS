# App 操作流程实测 · 2026-10-01

本轮修复确认停课后的红屏，并在 Android 模拟器内实际执行主要操作。没有将后端接口测试或静态页面截图当作 App 操作通过的证据。

## 本轮发现和修复

| 问题 | 修复与验证 |
| --- | --- |
| 确认停课后红屏 | 课程变更的 before/after 是课次列表，原保存摘要按单条事项访问 title，触发 String/int 下标类型错误。按操作种类生成摘要；真实 App 确认、再打开对话、撤销均通过。 |
| 删除课程后停在空详情页 | 先退出已删除资源的详情，再更新课表和事项数据。实际编辑、删除、返回均通过。 |
| 删除最后一个学期触发空值异常 | 旧首页监听器绑定学期和登录代次，失效时停止时钟和读取；管理页退出时保护空学期；日程页补同类保护。删除后回到创建入口，在线空列表不再残留“正在更新本机课表”的提示。 |
| 无截止时间任务默认“提前一天”提醒 | 没有可用截止时刻时，直接选择独立提醒时刻，不要求编造事项时间。前端判断与后端提醒锚点规则一致。真实 App 添加提醒后，任务时间仍未设置。 |
| 只改考试地点也强制填写改期原因 | 补充说明改为选填并折叠；内部审计保留默认原因，默认原因不重复显示给用户。 |
| 修改正式考试会把“仅作参考”改成占用时间 | 保留用户的预留选择，确认状态与是否占用独立。真实 App 改地点后日期精度、参考状态均保持，界面明确显示“仅作参考”。 |
| 考试修改后还有一轮无效操作和空提示 | 保存成功直接返回，显示简短反馈；不展示没有提醒、没有影响的计划或未变化的复习截止。只改地点时直接比较地点。移除考试页重复标题和空学期重复介绍。 |

## 测试方法与范围

- 设备：Medium_Phone_33 / emulator-5554。使用独立的 cn.semesteros.semester_os.qa 包，不清除正常 App 的账号和课表。
- 真实 SemesterApp、真实本机缓存、HTTP 后端和模型。主要记录流程通过注册界面建立测试账号；补充控制测试用 API 准备匿名账号、学期、任务和考试，随后每项被记录的操作均通过 App 控件执行。
- QA 后端只监听本机 8874，SQLite 和媒体保存在 output/verification；不读取生产数据库配置。学校课表使用匿名解析结果进入生产导入预览；不冒充已测试学校登录和网页提取。
- 每次动作后检查 Flutter 异常，保存实际设备截图，并读取真实后端状态交叉核对。点击未命中视为失败，等界面绘制完成后再操作。
- 录音使用真实 Android 录音器，测试按住、上滑取消和回到键盘；测试包事先授予系统麦克风与通知权限，取消后未生成上传来源。

两组最终功能流程为 41 + 22 个检查点，其中各一个是测试结束标记，合计 **61 个实际操作检查点**。完整 Flutter 回归 **408 项通过**，Dart 检查无问题。单独补充的管理流程用于快速复测删除与空学期边界，不重复计数。

| 范围 | 实际执行 |
| --- | --- |
| 账号与身份 | 注册、引导资料保存、手动修改资料、退出、恢复码找回、重新登录和云端数据保留 |
| 学期与课程 | 新建、切换、修改名称和节次加减、导入确认、重导替换、手工补课、编辑课程、删除课程、删除有记录的最后一个学期 |
| 助手课程操作 | 范围停课、确认后显示、再次打开保存结果、撤销、保持时长调课与撤销 |
| 个人任务 | 无截止创建、查看详情、修改耗时、提醒、完成及撤销；手工编辑、实际用时与剩余更新、完成、恢复、取消 |
| 活动与考试 | 活动只有开始时间时记录、补地点、提醒、取消及撤销；考试记录、仅日期更正、参考状态、完成及撤销；复习任务创建、地点修改确认和自动返回 |
| 批量与计划 | 两组记录一次确认与撤销；学习时间设置、最早开始、生成保存与撤销、锁定、显式解锁并取消，取消计划不改变剩余工作 |
| 输入与查询 | 语音切换、真实录音取消、键盘恢复；只读问题不产生保存预览；拒绝预览不写入事项；四个主页面与统计日期范围切换 |
