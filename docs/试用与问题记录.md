# 一周试用怎么进行

先使用测试账号走完导入、记录、修改、提醒和删除，再邀请愿意参与的同学使用自己的账号。尚未开始实际招募，本文件不是试用成果。

建议每天按自然需要使用，不要求完成指定数量，也不要求刻意频繁打开。

| 场景 | 观察什么 |
| --- | --- |
| 第一次使用 | 能否自行导入课表，是否知道如何记录通知 |
| 群通知与口语 | 日期、节次、本人职责是否理解正确；纠正一次能否修好 |
| 断网与后台 | 保存结果是否明确；返回时是否继续核实 |
| 日常查看 | 是否能通过首页、搜索或桌面卡找到所需事项 |
| 提醒 | 真实触发时间、手机型号、系统版本、权限和电池设置 |
| 完成与撤销 | 是否误操作；能否看懂修改范围并恢复 |

App 的“账户 → 反馈问题”只上传用户填写的描述和期望，不自动附带通知、录音和聊天记录。愿意提供原文时先去除姓名、学号、手机号等无关个人信息。

开发者记录：日期、版本、手机与系统、操作步骤、实际结果、期望结果、能否复现、修复版本、复测结果。一次偶发网络错误和持续的理解错误分别记录，不把提交反馈的人数当成全体使用者满意率。

服务器可运行 `python scripts/assistant_quality_report.py --days 7 --output output/verification/assistant-quality.json`。该报告只统计真实记录的请求状态与处理耗时，不提供未经人工核验的“识别准确率”。

一周后汇总最常见的问题和用户放弃操作的原因，再确定下一轮开发。不预先填写人数、成功率或节省时间。
