# 试用意见与问题记录

适用版本1.1.1，2026-10-17。

## 已有意见的来源

用户提供过16段学生口吻的反馈文字，涉及不同年级、班委、学生会、考研和竞赛场景。项目尚未核验这些文字是否来自16位独立参与者，也没有对应的连续使用日志、问卷和统一访谈记录。因此这里只整理意见，不据此计算人数、留存、满意度或提效比例。

| 主题 | 反馈提到的情况 | 当前情况与后续核对 |
| --- | --- | --- |
| 通知转日程 | 群消息和截图省去重输，但日期仍需核对 | 保留识别文字与原文、预览编辑及保存确认 |
| 新手入口 | 功能较多，不知道先做什么 | 使用说明分课程、通知、任务；手动记录可先只填必要信息，仍需真实新用户观察 |
| 学校适配 | 未适配学校无法直接导入 | 当前两所，其他学校使用手动录入；新增学校需页面样本和回归 |
| 估时与执行 | 实际用时超预估，临时安排打乱计划 | 记录进度、调整剩余工作、固定与重排；个人耗时学习和自动复盘尚未实现 |
| 请假理解 | 把“已请假”误解成向学校申请成功 | 文案说明仅记录已办好的具体课次，已请假课次从当前日程隐藏 |
| 系统入口 | 喜欢桌面查看下一节课 | 已有桌面卡片和用户开启的进行中通知，需要继续观察厂商设备行为 |
| 手动与AI | 简单小事手动更快，复杂通知更适合助手 | 保留手动新增、编辑及批量操作，助手共用同一份记录 |
| 使用习惯 | 有人没有记日程习惯，后续减少打开 | 需要访谈和使用日志确认原因，不能仅凭功能数量推断需求 |
| 使用阶段 | 高年级更关心面试、毕业设计等 | 日程、任务、考试和期限可统一记录，具体体验继续验证 |
| 标签 | 同类名称碎片化，找不到关联事项 | 1.1.1自动归并同类标签，点击标签查看跨学期记录 |

## App内反馈

入口：“账户 → 反馈问题”。提供问题类别、操作和结果、期望处理及App版本。开发者通过 `scripts/view_feedback.py` 查看服务器记录，见[维护说明](部署与维护.md)。当前未提供反馈工单状态和应用内回复。

提交有效问题时尽量记录：版本、手机及系统、操作入口、输入原话（先脱敏）、实际结果、期望结果、发生时间和复现步骤。模型理解问题还需要保存后的字段或预览；提醒问题还需权限、系统电池设置和是否强行停止。

## 后续验证记录格式

| 字段 | 需要填写 |
| --- | --- |
| 样本与同意 | 匿名编号、招募方式、是否同意引用 |
| 环境 | App版本、系统、设备、网络和权限 |
| 场景 | 原输入、已有课程或任务、操作目标 |
| 观察 | 实际步骤、核对与改错、成功或失败 |
| 后续 | 问题编号、修复版本、复验结果 |

引用原话时保留原意，说明是否做过精简；涉及姓名、群聊或账号时先脱敏。合成模拟器场景、用户意见和正式用户研究分别记录。
