# 日程助手开发与验证

2026-09-27。本轮是本地开发，不是产品发布；未改变版本号、未制作APK、未修改云端。固定日程基础见22，整体待完成范围仍以19为准。

## 实际接入的能力

App的“＋记录”内提供一个“日程助手”入口，文字新增与修改不再要求先选择解析类别。旧文字解析与操作路由仍兼容已有页面；图片、语音和手工入口保留。

- 多轮对话：保存会话和每轮请求，支持最近对话、重新进入恢复、轮询进度和停止处理。
- 真实查询：读取当前用户、当前学期的课程、固定活动、任务截止和个人计划；从结果卡进入详情。
- 真实计算：占用时长按时间并集计算，保留计划时长与实际投入的区别；查空闲使用学习时间设置并扣除固定安排、个人计划和缓冲。结束未知的跨日活动会要求补充信息。
- 业务操作：新增日程和任务；修改或取消一般固定日程；修改任务名称、预计剩余时长、拆分方式及事项提醒。先显示具体预览，再由用户点击确认保存。
- 可信确认：差异卡显示日期范围、确定性、地点和提醒等实际变化。新增只直接展示主要字段，其他配置和原始内容可展开。同名检索先消歧；课程与考试时刻不通过一般日程工具修改。
- 恢复与一致性：发送请求ID与确认回执可重放；业务变更和助手回执在同一数据库事务提交。旧预览过期或数据版本变化时拒绝应用。确认响应丢失后恢复会话会同步本机课表、任务和提醒。旧轮询结果不能覆盖新状态。

这不是“AI可以操作整个App”的完整实现。当前没有把自动规划／重排、所有撤销操作、图片／语音来源和长期偏好接入同一会话，也没有完成独立统计页面及全量视觉重构。现有手工功能继续可用。

## 实现与边界

新增`agent_api.py / agent_runtime.py / agent_tools.py / agent_model.py`。接口沿用`/api/v1/agent`，协议命名不用于表示产品版本。新增迁移`0011_agent_sessions`，存储用户绑定的会话、请求、工具消息、执行位置、候选和回执。

采用LangGraph 1.2.12组织模型节点与工具节点，保留当前模型服务与工具调用协议。[LangGraph工具循环说明](https://docs.langchain.com/oss/python/langgraph/quickstart)、[模型工具调用协议](https://api-docs.deepseek.com/guides/tool_calls/)。工具身份、学期、版本与确认令牌由服务端生成，模型不能直接执行SQL、HTTP或应用候选。

与18的候选方案相比，本次使用业务数据库内的事务检查点，而没有同时接入另一套LangGraph检查点表。每个节点提交完整状态后才进入下一个节点；worker租约过期后从该位置继续。这样操作候选、工具结果和执行位置可以保持同一事务，确认后的业务写入和回执也不存在第二次提交间隙。已验证在模型返回工具请求后中断并恢复；尚不声称所有部署故障均已覆盖。

请求立即返回作业ID，复用独立worker处理；没有让手机HTTP连接一直等待模型。当前worker交替处理媒体和助手作业，长媒体作业仍可能增加排队时间，需要后续并发与资源测量。每轮最多6次模型调用、12次工具调用，最多2次参数修正；检查90秒处理预算，单次外部请求另有25秒超时。该数值是工程限制，不是响应速度承诺。每账号共用现有解析频率限制。

历史上下文取最近8轮并限制文本体积，保留完整工具请求／结果组；不转发被取消时留下的孤立工具调用。不启用第三方追踪上传。真实模型验证仅发送合成内容。

框架依赖解析发现现有`websockets 17.1`与框架SDK的`<17`约束冲突，开发依赖锁定为16.0，其他原有锁定依赖保留。依赖检查通过；并未安装或替换服务器环境。最初的临时虚拟环境继承到了系统Conda依赖，不能用于有效验证；最终所有业务测试均使用项目`services/api/.venv`。

## 验证与发现

测试先验证缺失会话接口404和未实现UI恢复，再实现对应行为。后续回归覆盖账号隔离、未确认不写入、重复确认、过期预览、工作中取消、工具边界崩溃恢复、事务中断回滚、同名消歧、旧操作入口不能绕过助手确认、占用去重和跨日未知结束。

真实模型第一次测试失败：工具把提醒数组填成数字，参数修正时甚至省略提醒。已将工具参数从自由字典改为完整类型Schema，并提供字段类型错误。最终“新增带提醒的组会→追问改地点→查询并计算占用→暂定第14周通知”在三个独立合成账号中重复执行，12轮通过，包含实际工具请求和结果，不是解析接口伪装成工具调用。这个样本规模不能代表任意输入的准确率。

独立审查和恢复测试修复了：跨日未知结束的空闲误判、确认卡缺失确定性及日期范围、账号锁与请求锁的顺序冲突、拒绝操作与旧入口的并发边界、已保存回执恢复后未同步提醒、旧轮询响应覆盖完成状态。

本次PostgreSQL完整124项、Flutter完整91项通过，Flutter静态分析无问题；最终微调后相关Agent回归再次通过。存在一项上游Starlette弃用警告，不影响测试结果。本机证据：

- `output/agent-backend-full.log`：PostgreSQL完整回归。
- `output/agent-flutter-full.log`：Flutter完整回归（单并发）。
- `output/verification/agent-model.json`：12轮真实模型的调用数、工具名、耗时与Token用量。
- `output/verification/agent-ui/agent-change-preview.png`：实际Flutter控件渲染的确认界面。
- `output/verify_agent_migration.py`：在临时PostgreSQL schema升级到0011、降到0010、再次升级；不修改应用schema。

没有安装到物理手机或模拟器，没有验证真实通知送达、键盘体验及性能；Widget截图不等同真机验收。
