# 学期、课程与教务重导入

维护入口在“学期 → 管理学期与课表”。这些操作使用当前账号、明确学期及数据版本；修改预览与保存回执必须对应同一范围，旧请求失效后重新读取。

## 学期维护

- 编辑名称、首周周一、总周数和节次。新增 / 移除节次有明确入口；开始与结束同窗编辑，取消不写入。节次保留任意分钟，当天结束晚于开始。
- 修改时间骨架前核对旧 / 新差异。总周数不能低于课程实际使用的最大周次，课程不能引用已移除节次；已有个人计划或已确认调课的依赖须明确处理，不静默移动固定安排。
- 删除先展示作用范围，再明确确认。该学期的课程、事项、日程、个人计划、来源、助手对话及相关历史按预览清理；其他学期与账号不受影响。删除最后一个学期后回到创建入口。

## 课程与重导入

课程编辑保留名称、教师、地点、星期、周次、节次、真实整段钟点和免听状态。同一课程有多组授课模式时，先选具体组；课程删除的实际范围由预览列出。删除课程保留相关任务，但解除课程关联，历史原因仍留在事项修订中。

教务重导入先检查来源学校 / 学期与本机校历。校方钟点优先使用明确读到的值；首周不一致时可调整或明确保留本机设置，确认前不改变日历。无首周、未知实践时刻或免听不转成虚构占用。

变化课程展示旧 / 新信息，勾选后才替换；同名不能唯一匹配时拒绝猜测。旧教务课程未在新课表出现时默认保留，只有选择后才移除；移除限制在相同学校与来源学期，手工添加或手工修正课程不纳入自动移除。超出周数或缺少节次时指出具体值，并提供返回设置的入口。

黑大附加考试 / 实践与课次使用同一核对流程；重复导入不重复创建，学生已编辑或取消的附加记录保留。真实学校登录会话只在学校原页建立，Chrome 会话不会转移到 App。

## 数据、来源与提醒

学期 / 课程的修改和删除检查修订号；并发变化返回冲突，不用旧预览覆盖新记录。删除学期时，媒体清理任务与数据库删除在同一事务提交；文件删除失败可重试，不在提交前移走仍被引用的文件。

本机缓存、草稿及待投递提醒按账号和学期清理；另一设备删掉学期后，同步空目录也须移除旧缓存并重算本机提醒。确认后的业务变化、提醒同步结果与设备实际投递分别核对。

维护行为可通过 [App 流程回归](2026-10-01-App流程实测.md)的管理工作流复查；教务特殊范围见[黑大接入](2026-10-03-黑龙江大学教务适配验收.md)。当前源码与清理前已验证安装包的差异见 [README](../README.md)，本文件不沿用旧阶段 APK、测试数量或“尚未安装”结论。
